# 옥상 폐쇄와 직전 층 왕복 작업 기록

> 작업일: 2026-08-09  
> 작업 단위: 옥상 종료 안전 검사와 슬라이딩 2개 층 이동  
> 상태: 구현·자동 검증 완료

## 문제

- 옥상 미션 뒤 3층 문은 열리지만 전원이 내려와도 옥상이 계속 접근 가능해 영구 안전지대가 될 수 있었다.
- 층 이동은 직전 층에서 현재 활성 층으로 내려가는 방향만 지원했다.
- 다음 단계를 완료할 때 두 단계 이전 층에 AI나 빙결된 팀원이 남아도 문 상태가 즉시 바뀌었다.
- 서버가 층을 닫더라도 클라이언트가 갱신된 접근 층 목록을 받을 이벤트가 없었다.

## 구현

- 진행 상태에 `closing_pending_floor`와 실제 폐쇄 층 집합을 추가했다.
- 옥상 완료 후에는 `ROOF + F3`을 열되 옥상을 폐쇄 대기로 표시한다.
- 살아 있거나 빙결된 모든 도망자가 옥상을 떠나는 순간 옥상을 닫고 `accessible_floors`를 `F3`으로 갱신한다.
- 다음 단계에서 제외될 층에 팀원이 남아 있으면 단계 완료를 거부하고 actor ID를 오류로 알려 준다.
- 계단 전이는 actor의 현재 층을 기준으로 방향을 판별해 현재 층과 직전 층 사이를 왕복한다.
- 닫힌 층과 아직 열리지 않은 층은 같은 서버 권위 접근 목록으로 거부한다.
- 인간과 AI의 층 이동 이벤트에 최신 진행 상태와 실제 폐쇄 층을 포함했다.
- 클라이언트는 활성 층에서는 직전 층 복귀 계단을, 직전 층에서는 활성 층 진입 계단을 표시하고 가까운 계단에서 `E` 입력을 서버에 보낸다.

## 기획 교차 확인

- 2층 진행: 2층↔3층
- 1층 진행: 1층↔2층
- 파이널 진행: 선택된 파이널↔1층
- 두 단계 이전 층은 actor 안전 검사 뒤 폐쇄
- 옥상은 전원 하강 뒤 폐쇄되어 안전지대 악용 불가

## 검증

- 진행·층 이동·수직 미션 선별 테스트 `68 passed`
- 전원 하강 전 옥상 유지, 마지막 actor 하강 후 폐쇄 테스트 추가
- 닫힌 옥상 재진입 거부 테스트 추가
- 현재 층↔직전 층 왕복 테스트 추가
- 폐쇄 예정 층의 잔류 actor가 단계 완료를 막는 테스트 추가
- 클라이언트 프로덕션 빌드 통과
- 클라이언트 린트 오류 0개(기존 경고 유지)
- compact school 계약 검증 통과
