# 수직 미션 진행 복구 작업 기록

> 작업일: 2026-08-09  
> 작업 단위: 옥상 협동 튜토리얼과 층별 미션 안내·오류 피드백  
> 상태: 구현·자동 검증 완료

## 사용자 관찰

- 현재 미션이 실제 플레이에서 다음 단계로 진행되지 않는다.
- 옥상에서 AI 동료가 신호 장치까지 이동해도 정찰 보고만 하고 협동 행동을 수행하지 않는다.
- HUD는 내부 phase 문자열과 한 줄 설명만 보여 주어, 지금 누가 무엇을 해야 하는지 알기 어렵다.
- 층 이동이 거부돼도 클라이언트가 해당 실패 이유를 표시하지 않는다.

## 원인

1. 옥상 동료는 동·서 신호기로 이동하지만 도착 시 목표를 메모리에 완료 처리하고 `vertical_objective` 보고만 생성한다.
2. 중앙 신호가 아직 켜지지 않은 상태에서 동료가 먼저 도착하면 이후 점등 순서가 넘어와도 목표를 다시 평가하지 않는다.
3. 옥상 HUD는 세 장치의 진행 수, 다음 담당자, 플레이어의 대체 조작 가능 여부를 표현하지 않는다.
4. 서버는 `use_floor_transition` 거부 이유를 보내지만 WebSocket 클라이언트의 오류 표시 분기에 이 action type이 빠져 있다.

## 구현 결정

- 옥상 역할을 `플레이어=중앙`, `AI 동료 1=동쪽`, `AI 동료 2=서쪽`으로 명시한다.
- AI는 담당 신호에 도착하면 준비 상태를 유지하고, 자기 신호가 현재 점등 순서가 되는 즉시 서버 권위 판정으로 동기화한다.
- 준비가 너무 이른 경우 메모리 완료로 소모하지 않고 다음 판단 틱에 다시 확인한다.
- 동료가 빙결·우회 등으로 수행하지 못할 때는 플레이어가 현재 점등 신호를 직접 조작할 수 있어 진행이 막히지 않게 한다.
- HUD에 사람이 읽을 수 있는 단계명, 진행 수, 현재 행동, 역할 분담을 표시한다.
- 미션·층 이동 상호작용의 서버 거부 이유를 자막으로 전달한다.

## 완료 조건

- 플레이어가 중앙 신호를 켜면 이미 도착한 AI 동료들이 동쪽과 서쪽 신호를 순서대로 켜고 옥상 단계가 완료된다.
- 잘못된 순서·거리·층 이동 잠금은 서버에서 계속 거부된다.
- 옥상 HUD에서 `0/3`부터 `3/3`까지 진행과 다음 담당자를 확인할 수 있다.
- 기존 플레이어 단독 3신호 조작 경로도 유지된다.
- 층별 미션 및 WebSocket 회귀 테스트, 클라이언트 빌드·린트가 통과한다.

## 기획 교차 감사

- 기획 2: AI를 장식용 추종자가 아니라 독립 역할을 맡는 협동 actor로 사용한다.
- 기획 3·4: 옥상 의미 슬롯과 서버 권위 좌표·순서 판정을 유지하며 탑다운 진행을 복구한다.
- 기획 5: 금기어는 공개하지 않고, AI 발화도 기존 회피·검사 경로를 그대로 통과한다.

## 검증

- 옥상 AI 조기 도착·순서 대기 단위 테스트 추가
- 플레이어 중앙 → AI 동쪽 → AI 서쪽 → 3층 개방 통합 테스트 추가
- 층별 미션·WebSocket 관련 선별 테스트 `110 passed`
- 서버 전체 테스트 `308 passed, 1 skipped`
- 클라이언트 프로덕션 빌드 통과
- 클라이언트 린트 오류 0개(기존 경고 유지)
- compact school 계약 검증 통과
