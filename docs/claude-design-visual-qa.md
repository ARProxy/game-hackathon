# Claude Design 시각 QA

2026-08-08 기준 ZIP 원본과 실제 게임 WebGL 렌더를 비교한 기록이다. 자동 캡처는 1440×900 Headless Chrome WebGL 환경에서 테스트 타이틀을 클릭해 서버 게임에 진입한 뒤 수행했다. 캡처 이미지는 제출 코드에 포함하지 않고 임시 QA 산출물로만 사용했다.

## 확인한 원본 구도

- `screenshots/school-finish.png`: 중정, 순환 복도, 계단, 다층 외벽 전경
- `screenshots/hall-check.png`: 1층 승객용 엘리베이터와 승강장 조명
- `shots/03-ev3.png`: 승강기 문틀 안쪽에서 바라본 복도

## 현재 게임 캡처 결과

### 3인칭 플레이

- 1440×900 WebGL 캔버스가 정상 생성되고 최신 학교 형상이 렌더됐다.
- 플레이어 손전등은 전방 벽과 바닥을 실제로 밝힌다.
- 옥상과 상층 통로는 원본 자유 시점보다 시야가 좁고 간접광이 약하다.
- 가까운 벽 뒤에서 카메라 충돌이 작동할 때 캐릭터가 화면 높이의 약 1/3을 차지한다.
- 공간 누락보다는 플레이 카메라·현재 위치·야간 조명의 차이가 첫인상 차이를 크게 만든다.

### CCTV 전경

- 최신 ㄷ자 본관, 중앙 운동장·중정, 옥상 난간, 계단 코어가 확인됐다.
- 구형 맵이 대신 렌더되는 현상은 재현되지 않았다.
- CCTV 보정광에서는 건물과 운동장 경계, 창, 순환 동선이 구분된다.
- 실제 플레이의 어두움은 형상 누락이 아니라 3D 야간 렌더 조건에 집중돼 있다.

## QA 중 발견해 수정한 문제

옥상 미션 완료 직후 서버는 F3에 술래를 공개한다. 기존 클라이언트는 행위자 종류와 무관하게 모든 `actor_floor_changed`를 “F3 구역으로 이동했습니다”라고 표시해 플레이어가 자동 이동한 것처럼 오해하게 했다. 이제 내 이동은 기존 문구, 술래 이동은 출현 경고, AI 이동은 동료 이동 자막으로 분리한다.

### 원본 대비 렌더·이동 회귀

- 원본에서 별도 투명 재질로 처리한 유리와 물이 일반 도장 재질로 합쳐져 불투명하게 보이던 문제를 분리했다.
- TypeScript 포팅 중 빠진 원본 normal map 강도를 복원했다.
- 원본의 2048 달빛 그림자와 1024 손전등 그림자 설정을 실제 게임 렌더러에 연결했다.
- 플레이어의 10Hz 좌표 저장이 전체 학교 장면을 다시 reconcile하던 경로를 메모이제이션으로 차단했다.
- 문은 `OriginalDoors` 한 경로만 렌더한다. 정적 문 배치는 함께 렌더하지 않는다.

### 원본 렌더 계약 재대조

실제 `업그레이드 2.zip`의 `campus-renderer.js`와 R3F 어댑터를 줄 단위로 다시 비교해 다음 차이를 교정했다.

- `fixtures` 150개는 형상이 아니라 동적 광원 후보 데이터다. 이를 발광 박스로 중복 렌더하던 경로를 제거했다.
- 동적 실내광은 원본처럼 카메라에서 가까운 16개만 0.2초마다 다시 선택한다. 조도 `1.5`, 거리 `13m`, 감쇠 `2`를 복원했다.
- 원본에 없던 120m 보조 바닥 박스를 제거하고 캠퍼스 데이터의 바닥·슬래브만 렌더한다.
- 원통 형상의 분할 수를 원본의 12로 복원했다.
- 서버의 `accessible_floors`는 문·이동 권한이지 건물 가시성 계약이 아니다. 게임 모드에서는 전체 학교 외형을 유지하고 개발용 비교 모드에서만 층을 숨긴다.
- 개발 서버에서 `Tab`을 누르면 원본 기본 오빗 `target=(-24, 2, -30)`, `distance=118`, `yaw=0.72`, `pitch=0.62`, `FOV=58`로 전환한다.
- 원본의 블룸 `0.5`, 필름 그레인 `0.16`, 비네트와 카메라 추종 달빛을 월드 렌더에 복원했다.

이번 실행 환경에는 제어 가능한 브라우저가 연결되지 않아 자동 스크린샷 비교는 수행하지 못했다. 캠퍼스 계약, TypeScript 빌드, 린트와 전체 서버 테스트를 통과했으며, 실제 화면 비교는 개발 서버에서 `Tab` 원본 비교 모드로 이어간다.
