# 계단실 구조 재설계 단위

## 사용자 발견 문제

옥상 북서 방화문을 열고 정면으로 들어가면 계단을 밟지 못하고 1층까지 떨어졌다. 계단의 외형도 일부 경사로에만 난간이 있고 문, 층계참, 두 계단 레인이 하나의 구조로 이어지지 않아 실제 건축물처럼 읽히지 않았다.

## 원인

- 옥상 방화문 중심은 `[-36, 10.8, -39.62]`이다.
- 기존 최상단 층계참은 오른쪽 하강 레인 `x=-33.65`만 받쳤다.
- 문 중심 `x=-36`과 층계참 사이에는 충돌 바닥이 없었다.
- F2·F3·옥상 슬래브에는 같은 위치의 계단 보이드가 수직으로 뚫려 있다.
- 따라서 문을 정면으로 통과한 캐릭터 캡슐은 세 층의 빈 공간을 지나, 보이드가 없는 F1 슬래브에서 멈췄다.

이 문제는 옥상 한 곳의 좌표 오류가 아니라 각 층의 문과 스위치백 계단이 구조적으로 연결되지 않은 공통 결함이었다.

## 구조 결정

- 북서·남동 코어의 F1–F2, F2–F3, F3–옥상 스위치백 6개를 같은 구조 계약으로 재작성했다.
- 각 상부 층계참을 한쪽 레인 폭에서 코어 전폭 `7.45m`로 확장했다.
  - 문 정면을 받친다.
  - 오른쪽 상부 레인과 이어진다.
  - 같은 높이에서 다음 하강 계단의 왼쪽 하부 레인으로 연결된다.
- 각 경사로의 안쪽과 바깥쪽에 모두 연속 충돌 난간과 보이는 손스침·기둥을 배치했다.
- U턴 중간참의 먼 가장자리에 전폭 난간을 추가했다.
- 층계참 안쪽은 두 레인 입구만 비우고 중앙 보이드를 난간으로 차단했다.
- 시각 계단, 보이지 않는 경사 충돌체, 층계참, 난간 장벽의 축을 동일 데이터에서 생성한다.

## 플레이 동선

옥상 방화문에서 3층 복도까지의 실제 보행선을 `doorToDoorDown` 계약으로 명시했다.

1. 옥상 방화문을 통과해 전폭 층계참에 선다.
2. 오른쪽 레인으로 돌아 첫 경사로를 내려간다.
3. 난간으로 닫힌 중간참에서 U턴한다.
4. 왼쪽 레인 경사로를 내려간다.
5. 3층 전폭 층계참을 거쳐 3층 방화문으로 나온다.

AI 동료 애니메이션이 사용하는 기존 `down` 경로와 서버 층 권위 전환점은 바꾸지 않았다. 플레이어의 실제 보행 안전 구조만 그 경로 전후의 문까지 확장했다.

## 회귀 방지

- 6개 계단마다 아래 6종 연속 난간의 존재와 충돌 속성을 검사한다.
  - 하부 경사 외측·내측
  - 상부 경사 내측·외측
  - U턴 중간참 외곽
  - 층계참 중앙 보이드
- 옥상 방화문 중심과 오른쪽 하강 레인이 같은 층계참 위에 있는지 검사한다.
- 방화문→상부 층계참→두 경사로→중간참→3층 층계참→3층 방화문 경로를 약 `0.12m` 간격으로 샘플링한다.
- 모든 샘플에서 슬래브, 층계참 또는 경사 충돌체의 윗면이 발을 연속 지지해야 검증이 통과한다.
- 서버 수직 맵 계약은 문-문 보행선의 시작과 끝이 실제 의미 슬롯과 일치하는지 검사한다.
- 난간 변경 후 서버 2D 충돌 계약을 다시 내보내 클라이언트 구조와 정합성을 유지한다.
