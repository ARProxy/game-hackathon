# 구현 기준점 — 비공개 금기어와 ㅁ자 학교 옥상 슬라이스

> 작성일: 2026-08-09  
> 목적: 플레이어 이동 끊김과 AI 동료 정지 문제를 분석하기 전, 현재 구현 상태를 재현 가능한 기준점으로 보존한다.

## 1. 이번 기준점의 범위

이 기준점은 두 개의 연속된 기획 변경을 함께 포함한다.

1. 기획 5에 따라 게임 전 질문과 금기어 공개 화면을 제거하고, 플레이 중 대화를 기반으로 비공개 금기어를 형성·교체하는 흐름으로 전환했다.
2. 기존 대형 캠퍼스 대신 48×40m 폐쇄형 ㅁ자 학교를 구조 정본으로 만들고, 옥상에서 시작해 아래층으로 내려가는 첫 수직 슬라이스를 구현했다.

아래의 미해결 관찰은 이 기준점에서 수정하지 않는다. 다음 작업은 이 상태를 출발점으로 원인을 분리해 진단한다.

- 새 맵이 이전 캠퍼스보다 상당히 좁게 체감된다.
- 플레이어 이동 중 화면이 떨리고 프레임이 뚝뚝 끊겨 보인다.
- AI 동료 캐릭터가 목표를 수행하지 않고 제자리에 머문다.

## 2. 비공개 동적 금기어

- `game-design-v5.md`를 금기어 경험의 최신 정본으로 추가했다.
- 일반 게임 시작은 사전 질문·금기어 공개 없이 곧바로 옥상 플레이로 진입한다.
- 첫 유효 발화 3회는 관찰 구간이며, 첫 프로필은 네 번째 발화부터 적용된다.
- 이후에는 유효 발화 5회와 최소 유지시간 45초를 모두 만족할 때 최대 두 단어를 교체한다.
- LLM/Ollama는 후보 추천만 담당하고, 서버 검증기와 로컬 폴백이 실제 적용 단어를 확정한다.
- 인간 클라이언트에는 현재 단어, 개수, 일치 단어와 교체 시각을 보내지 않는다.
- AI 동료는 현재 금기어를 우회해서 말하며 정답을 누설하지 않는다.
- 파이널 진입 시 프로필을 잠그고, 전체 이력은 결과 화면에서만 공개한다.

## 3. 새 학교 구조 계약

구조 정본은 `client/src/game/compactSchoolData.js`다.

| 항목 | 현재 계약 |
|---|---:|
| 건물 외곽 | 48×40m |
| 형태 | 폐쇄형 ㅁ자 중정 |
| 층고 | 3.6m |
| 순환 복도 폭 | 4.2m |
| 실내 의미 공간 | 24개 |
| 문 | 39개 |
| AI 순찰 노드 | 32개 |
| 서버 평면 장벽 | 826개 |

- F1·F2·F3에 동일한 구조 문법의 순환 복도와 방 베이를 배치했다.
- 북서와 남동에 두 개의 스위치백 계단 코어를 두었다.
- 옥상과 상부 계단 보이드에는 연속 난간 collider를 배치했다.
- 옥상에는 외곽·중정 파라펫, 계단실, 물탱크, HVAC, 안테나와 신호 콘솔을 배치했다.
- 구조물은 `wall`, `slab`, `stairRamp`, `landing`, `rail`, `parapet`처럼 역할을 명시하며 크기로 충돌 여부를 추측하지 않는다.
- 렌더러, Rapier, 서버 장벽과 AI 순찰 노드는 같은 구조 데이터에서 파생한다.

## 4. 이동과 충돌 기준

- 인간 플레이어의 Rapier capsule에 연속 충돌 감지(CCD)를 적용했다.
- AI 동료와 술래는 자신의 현재 층 높이에서 shape cast를 수행한다.
- AI의 쿼리는 고정 구조물뿐 아니라 닫힌 kinematic 문도 장애물로 취급한다.
- 서버는 연속된 위치 샘플의 속도뿐 아니라 두 점 사이의 벽 교차도 거부한다.
- 서버 술래의 기본 순찰 목표를 구형 맵 좌표에서 새 순환 복도 노드로 교체했다.

이 계약은 벽 관통 방지를 위한 기준이며, 이번에 보고된 카메라 떨림·이동 끊김의 원인이 해결되었다는 의미는 아니다.

## 5. 옥상 첫 수직 슬라이스

옥상 시작 팀은 안전한 북측 중앙에 생성된다. 첫 목표는 세 신호 장치를 다음 순서로 직접 동기화하는 것이다.

```text
중앙 신호 → 동쪽 신호 → 서쪽 신호 → 북서 방화문 개방 → F3
```

- 현재 차례인 콘솔만 황색 비콘과 상호작용 문구를 표시한다.
- 완료한 콘솔은 녹색 상태로 남는다.
- 서버가 actor의 층, 장치와의 거리, 입력 순서를 검증한다.
- 3/3 완료 전에는 `roof_to_f3` 방화문이 닫힌 collider 상태를 유지한다.
- 보조 남동 옥상 계단실은 첫 슬라이스의 우회로가 되지 않도록 잠겨 있다.
- 온라인 서버를 사용할 수 없는 환경의 데모 transport도 같은 순서를 사용한다.

## 6. 자동 검증

- 클라이언트 구조와 서버 장벽·AI 노드 계약의 완전 일치

## 7. 다음 진단 순서

다음 작업에서는 기능을 추가하기 전에 아래 순서로 재현하고 계측한다.

1. 플레이어 rigid body, 비주얼 group, 카메라가 서로 다른 주기로 보간되는지 확인한다.
2. 위치의 클라이언트 낙관적 갱신과 서버 권위 갱신이 되먹임을 만드는지 확인한다.
3. 새 고정 collider 826개가 물리 step과 렌더 프레임에 미치는 비용을 측정한다.
4. AI 동료가 의도를 받지 못한 것인지, 권위 위치 보정에 갇힌 것인지, shape cast가 시작점에서 계속 막히는지 분리한다.
5. 화면상 체감 면적과 실제 미션 밀도를 비교한 뒤 건물 치수 유지·확대 여부를 결정한다.

이 순서는 현재 증상의 원인을 아직 단정하지 않으며, 커밋 이후의 분석 작업을 위한 체크리스트다.
