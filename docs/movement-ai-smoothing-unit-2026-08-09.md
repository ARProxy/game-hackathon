# 이동·카메라 안정화와 AI 스냅샷 보간 작업 기록

> 작업일: 2026-08-09  
> 작업 단위: 이동 체감 안정화 기반  
> 상태: 구현·자동 검증 완료, AI 판단 품질은 후속 단위에서 개선

## 사용자 관찰

- 플레이어 이동 중 화면이 떨리고 프레임이 뚝뚝 끊겨 보였다.
- AI 동료가 옥상 시작점 부근에서 거의 움직이지 않았다.
- 동료와 술래의 이동 코드가 중복돼 수정 시 서로 다른 규칙이 생길 위험이 있었다.

## 원인

1. Rapier 물리 바디는 고정 틱을 보간했지만 캐릭터 비주얼은 바디 밖에서 원시 `translation()`을 다시 보간했다.
2. 플레이어 위치를 10Hz로 Zustand에 기록할 때 `Scene`이 전체 `players`를 구독하고 그 값을 다시 `position` prop으로 물리 actor에 전달했다.
3. 카메라는 매 프레임 여러 `Vector3`와 Ray를 만들고, 벽 충돌 유무에 따라 서로 다른 추종 속도를 즉시 전환했다.
4. AI actor는 서버 위치로 복귀하는 이동과 서버 목표로 향하는 로컬 이동을 동시에 수행해 스냅샷마다 앞뒤로 끌렸다.
5. 옥상 동료의 공통 목표가 시작점에서 가까운 중앙 장치라 자율 행동이 거의 보이지 않았다.

## 구현 결정

- 플레이어 비주얼을 `RigidBody` 자식으로 이동해 Rapier 보간 transform을 단일 정본으로 사용한다.
- 카메라·조명·상호작용은 로컬 `position`이 아니라 `getWorldPosition()`으로 플레이어 위치를 읽는다.
- `Scene`의 전체 플레이어 위치 구독과 위치 prop 되먹임을 제거한다.
- 카메라 벡터와 Ray를 재사용하고, 벽 충돌 거리를 연속적으로 감쇠한다.
- 서버 위치 스냅샷은 목표 방향으로 최대 한 판단 틱만 예측하고 도착 반경을 넘지 않는다.
- 동료와 술래의 충돌 인지 평면 이동을 공통 훅으로 추출한다.
- 옥상에서 두 동료는 각각 동쪽·서쪽 신호기를 정찰한다.
- 서버가 없는 데모 transport도 같은 동료 이동을 제공한다.
- 사용되지 않는 `CameraFollow`와 `cameraStore`를 제거한다.

## 기획 교차 감사

- 기획 1: AI 협동 actor와 술래가 실제 월드에서 이동할 기반을 복구했다.
- 기획 2: 플레이어 공전 대신 독립 목표로 움직이는 방향을 유지했다.
- 기획 3·4: 옥상 의미 슬롯과 서버 권위 위치를 사용하고, 벽 충돌은 인간·AI가 같은 맵 계약을 사용한다.
- 기획 5: 금기어 공개·판정 계약에는 변화를 주지 않았다.

## 남은 한계

이 단위는 이동의 연속성과 서버·클라이언트 좌표 충돌을 해결한다. AI가 왜 그 목표를 선택했는지 말하고, 미션 상태를 이해하고, 인간과 역할을 조정하는 판단 품질은 포함하지 않는다. 사용자 관찰상 이 부분이 여전히 “바보 같은 AI”로 체감되므로 별도 작업 단위에서 개선한다.
