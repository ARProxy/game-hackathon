## 0. 문서의 역할과 우선순위

기획 1은 『얼음, 땡!』의 원래 정체성과 핵심 규칙을 정의한다. 기획 2는 현재 구현을 A–Z로 감사한 결과를 바탕으로, 플레이어가 실제로 “게임”이라고 느끼기 위해 필요한 시작 경험, 선택, AI 행동, 추격과 멀티플레이 구조를 정의한다.

두 문서는 대체 관계가 아니라 **왕복 분석 관계**다.

### 읽는 순서

1. 기획 1에서 핵심 판타지와 불변 규칙을 확인한다.
2. 기획 2에서 현재 목표 경험과 개정된 행동 계약을 확인한다.
3. 구현 후 다시 기획 1로 돌아가 핵심 재미가 훼손되지 않았는지 검사한다.
4. 다시 기획 2로 돌아와 기능이 실제 선택과 피드백으로 체감되는지 검사한다.

### 충돌 우선순위

- 기획 2가 **명시적으로 개정**한 항목은 기획 2가 우선한다.
- 기획 2가 언급하지 않은 금기어, 빙결, 주문, 탈출의 핵심 규칙은 기획 1을 따른다.
- 구현 편의를 이유로 두 문서의 목표를 축소하지 않는다.
- 충돌이 불명확하면 구현하지 않고 의사결정 문서에 남긴다.

### 기획 2의 명시적 개정 항목

- 게임 진입 전에 시작 화면과 모드 선택 흐름을 둔다.
- 솔로 플레이와 멀티 플레이를 명확히 분리한다.
- 술래의 기본 상태를 고정 순찰이 아닌 능동 사냥으로 바꾼다.
- AI 동료의 기본 상태를 플레이어 공전이 아닌 독립 목표 수행으로 바꾼다.
- 솔로 도망자 팀은 인간 1명과 AI 동료 2명으로 구성한다.
- AI는 정답 프롭으로 직행하지 않고 모든 후보를 비교한다.
- 최종 주문의 완성 답안을 HUD에 그대로 노출하지 않는다.

## 1. 현재 문제 정의

현재 구현은 온보딩부터 탈출까지 완주와 패배가 가능한 닫힌 루프를 갖고 있다. 하지만 다음 이유로 완성형 AI 게임보다 기능 데모처럼 느껴질 위험이 있다.

1. AI가 세 후보를 비교하지 않고 정답 프롭의 키워드만 검사한다.
2. 틀린 이해, 낮은 확신, 확인 질문과 플레이어 교정이 없다.
3. 최종 주문 정답이 HUD에 그대로 표시된다.
4. 동일한 T1 문법이 세 번 반복되며 난도와 상황 변화가 약하다.
5. 술래가 목표 없이 순찰하는 시간이 길고 인간만 주된 판정 대상이다.
6. AI 동료가 독립적인 지능체보다 플레이어 주변 장식처럼 보인다.
7. 시작 화면 없이 곧바로 질의응답이 나타나 첫 60초가 입력 폼처럼 느껴진다.
8. 거대한 학교 맵과 제작된 구역이 실제 미션 동선에 충분히 사용되지 않는다.
9. 자동 구조가 강해 빙결과 구조의 선택 비용이 약하다.
10. 정적 전형 시간이 약 1.8~2.8분으로 3~5분 목표보다 짧다.

기획 2의 목적은 기능 수를 늘리는 것이 아니라, 이미 존재하는 핵심 콘셉트를 **선택 → 결과 → 피드백 → 재판단**의 게임 구조로 만드는 것이다.

## 2. 새로운 한 줄 정의

**『얼음, 땡!』은 말할수록 위치가 드러나는 어두운 학교에서, 각자 판단하는 AI 동료와 협력하고 인간과 AI 모두를 사냥하는 술래를 피해 금지된 대상을 찾아 탈출하는 음성 잠입 협동 게임이다.**

---

## 3. 플레이어가 반드시 느껴야 하는 것

한 판이 끝났을 때 플레이어가 다음을 설명할 수 있어야 한다.

1. 시작 전에 내가 선택한 캐릭터와 답변이 이번 판의 규칙에 반영됐다.
2. 말하면 술래가 나를 찾기 때문에, 말할 시점과 표현을 선택했다.
3. AI 동료는 내가 말하지 않아도 각자의 임무를 수행했다.
4. 내 설명이 모호하면 AI가 오해하거나 질문했고, 내가 표현을 고쳐야 했다.
5. 술래는 인간과 AI를 가리지 않고 계속 사냥했다.
6. 누군가 얼면 위치가 팀에 공유되고, 누가 구조할지 판단이 발생했다.
7. 마지막 주문은 화면의 정답을 읽은 것이 아니라 모은 단서를 사용한 결과였다.

## 4. 전체 화면 및 상태 흐름

```text
앱 실행
  ↓
시작 화면
  ├─ 게임 시작
  │    ↓
  │  모드 선택
  │    ├─ 솔로 플레이
  │    │    ↓
  │    │  캐릭터 선택
  │    │    ↓
  │    │  말하기 질의응답
  │    │    ↓
  │    │  금기어 공개·핵심 규칙 안내
  │    │    ↓
  │    │  한 판 시작
  │    │
  │    └─ 멀티 플레이
  │         ↓
  │       방 만들기 / 방 참가
  │         ↓
  │       대기방·캐릭터 선택·준비
  │         ↓
  │       플레이어별 말하기 질의응답
  │         ↓
  │       방장 시작·금기어 공개
  │         ↓
  │       한 판 시작
  │
  ├─ 설정
  └─ 나가기
```

게임 내부 상태는 다음을 따른다.

```text
TITLE → MODE_SELECT → SOLO_SETUP 또는 MULTI_LOBBY
→ CHARACTER_SELECT → SPEECH_ONBOARDING → FORBIDDEN_REVEAL
→ PLAYING → FINAL_SPELL → ESCAPE → RESULT
```

화면 전환은 클라이언트 임시 상태만으로 결정하지 않는다. 방, 플레이어, 준비, 캐릭터, 게임 시작 이후의 상태는 서버 권위를 따른다.

## 5. 시작 화면

### 5.1 목적

첫 화면에서 장르, 목표, 분위기와 입력 장치를 전달한다. 사용자가 준비되지 않은 상태에서 마이크 질문부터 받지 않는다.

### 5.2 구성

- 게임 로고: 『얼음, 땡!』
- 짧은 카피: `말하면 들킨다. 설명하고, 구하고, 탈출하라.`
- 배경: 손전등이 어두운 학교 복도를 훑고 멀리 술래의 붉은 경광이 지나가는 장면
- 주 버튼:
  - `게임 시작`
  - `설정`
  - `나가기`

### 5.3 게임 시작

`게임 시작`을 누르면 모드 선택 화면으로 이동한다.

- `솔로 플레이`: 인간 1명 + AI 동료 2명 + AI 술래 1명
- `멀티 플레이`: 2명 이상의 인간과 부족한 슬롯을 채우는 AI 동료 + AI 술래

### 5.4 설정

설정은 시작 화면과 게임 중 일시정지 화면에서 동일한 값을 사용한다.

- 전체 음량, 효과음, 환경음, 음성
- 마이크 장치 선택과 입력 테스트
- 음성 인식 언어
- 자막 표시와 크기
- 그래픽 품질, 그림자, 렌더 배율
- 마우스 감도와 Y축 반전
- 키 설정 확인
- 광과민성 보호: 붉은 경광 강도/빈도 완화

### 5.5 나가기

브라우저 보안상 탭을 자동으로 닫을 수 없으면 확인 창 뒤에 `이 탭을 닫아 게임을 종료하세요` 안내를 표시한다. 데스크톱 패키지에서는 실제 종료 동작과 연결한다.

## 6. 솔로 플레이 흐름

### 6.1 캐릭터 선택

질의응답 전에 플레이어 캐릭터를 선택한다.

- 캐릭터 카드에 외형, 이름, 색상과 역할을 표시한다.
- 초기 버전의 능력치는 동일하게 유지해 외형 선택이 정답이 되지 않게 한다.
- 선택한 캐릭터는 월드, HUD 색상, 결과 화면에 유지된다.
- AI 동료와 술래는 플레이어와 중복되지 않는 캐릭터를 배정한다.
- 두 AI 동료는 각각 독립된 감지, 기억, 목표와 판단 주기를 가진다.

### 6.2 말하기 질의응답

기존 면접형 질문을 게임 진입 경험으로 바꾼다.

- 시작 전에 마이크 테스트를 제공한다.
- 음성 입력과 텍스트 폴백을 모두 제공한다.
- 질문마다 제한시간 또는 빠른 진행 선택을 둔다.
- 답변이 인식됐는지 즉시 확인할 수 있다.
- 지원 가능한 단어가 부족하면 숨겨진 폴백을 사용하되, 결과 화면에서 실제 답변 기반 단어와 시스템 보충 단어를 구분한다.

질문은 단순 개인정보 면접이 아니라 연상 게임 형태를 우선한다.

- `어두운 교실 책상 위에서 발견한 세 가지는?`
- `비 오는 날 가방에 넣고 싶은 물건은?`
- `빨리 떠오르는 색과 음식 하나씩!`

### 6.3 규칙 공개

금기어만 보여주고 바로 게임으로 보내지 않는다. 10초 안에 다음을 전달한다.

- 금기어를 말하면 얼어붙는다.
- 모든 발화는 술래가 들을 수 있다.
- AI에게 금기어를 피해 설명해야 한다.
- 얼면 위치가 팀에 공유된다.
- 단서를 모아 주문을 완성하고 탈출해야 한다.

## 7. 멀티 플레이와 대기방

### 7.1 기본 구조

- 도망자 팀: 2~4슬롯
- 인간이 부족한 슬롯은 AI가 채운다.
- 술래는 기본적으로 서버 권위 AI다.
- 한 방의 최대 인원과 AI 보충 수는 방장이 설정한다.

### 7.2 진입

- `방 만들기`: 짧은 방 코드와 초대 링크 생성
- `방 참가`: 방 코드 입력 또는 초대 링크 사용
- 닉네임은 금칙어와 길이를 검증한다.

### 7.3 대기방 UI

- 참가자 슬롯과 연결 상태
- 인간/AI 구분
- 캐릭터 선택 상태
- 마이크 준비 상태
- 질의응답 완료 상태
- 준비/준비 해제
- 방장 표시와 시작 버튼
- 빈 슬롯 AI 채우기 설정
- 나가기와 방 해체 확인

### 7.4 시작 조건

- 모든 인간 플레이어가 캐릭터를 선택한다.
- 모든 인간 플레이어가 마이크 테스트 또는 텍스트 폴백 확인을 마친다.
- 모든 인간 플레이어가 준비 상태다.
- 방장만 시작할 수 있다.
- 캐릭터 중복, 준비 누락, 연결 끊김은 서버가 거부 사유를 반환한다.

### 7.5 멀티 질의응답과 금기어

- 질문은 각 플레이어의 화면에서 개별 진행한다.
- 답변 원문은 다른 참가자에게 공개하지 않는다.
- 공통 금기어와 개인 금기어를 서버가 구분한다.
- 게임 시작 전 모든 참가자의 응답 완료 여부만 공유한다.

### 7.6 연결 복구

- 새로고침이나 일시 단절 시 기존 플레이어 ID와 방 토큰으로 재접속한다.
- 유예시간 동안 캐릭터와 상태를 보존한다.
- 방장이 나가면 권한을 이전하거나 방 해체 여부를 명확히 알린다.
- 게임 도중 이탈한 슬롯은 설정에 따라 AI가 인계한다.

## 8. 핵심 게임 루프 2.0

```text
각 AI가 독립 목표를 선택해 탐색
  ↓
플레이어가 말할 필요와 들킬 위험을 비교
  ↓
우회 표현·공간·상황으로 AI에게 지시
  ↓
AI가 모든 후보를 비교하고 확신도를 계산
  ├─ 높은 확신: 행동
  ├─ 중간 확신: 확인 질문
  └─ 낮은 확신: 후보 보고 또는 대기
  ↓
결과가 정답·오해·위험 노출·단서 획득으로 이어짐
  ↓
술래가 시각·소리·빙결 핑으로 목표를 계속 사냥
  ↓
빙결 시 위치 공유·구조 담당 결정
  ↓
단서를 해석해 최종 주문 완성
  ↓
게이트 개방·술래 전력 추격·탈출
```

모든 주요 행동은 다음 네 요소를 가져야 한다.

1. 플레이어 또는 AI의 선택
2. 즉시 이해 가능한 피드백
3. 월드 상태의 변화
4. 다음 판단에 영향을 주는 결과

## 9. 술래 — 능동 사냥 모델

### 9.1 핵심 원칙

술래는 “순찰하다 우연히 마주치는 NPC”가 아니다. 게임이 진행되는 동안 항상 인간 또는 AI 도망자를 잡는 최상위 목표를 가진다.

단, 항상 정확한 위치를 아는 전지적 치팅 AI는 금지한다. 술래는 감지 정보와 마지막 목격 위치를 사용해 사냥한다.

### 9.2 감지 입력

- 시야: 거리 12m, 전방 시야각 100도, 벽 시야 차단
- 근접 발견: 반경 8m 안에서 시야가 확보되면 즉시 추격
- 청각: 일반 발화 반경 18m, 거리에 따라 오차가 있는 위치 추정
- 금기어/빙결 핑: 발생 위치를 정확한 강한 단서로 수신
- 발자국·문·트랩 등 최근 흔적
- 게이트 주문: 활성 게이트를 최고 우선순위로 설정

수치는 실플레이로 조정하되 서버와 클라이언트가 하나의 감지 계약을 공유한다.

### 9.3 목표 선택

술래는 모든 인간과 AI 도망자를 후보로 평가한다.

```text
위협 점수 = 감지 확신도 + 거리 + 최근 발화 + 빙결 여부
           + 게이트 근접도 + 고립 여부 - 경로 비용
```

- 인간만 고정 목표로 삼지 않는다.
- 더 가까운 AI가 소리를 냈다면 AI를 추격할 수 있다.
- 목표를 잃으면 마지막 목격 위치를 수색한다.
- 정보가 없으면 고정 웨이포인트 반복 대신 도망자가 있을 확률이 높은 미션 구역과 소리 발생 구역을 탐색한다.

### 9.4 상태 모델

```text
HUNT       정보가 없을 때 확률 높은 구역 탐색
INVESTIGATE 소리·흔적 위치 확인
DETECTED   시야로 목표 확인, 경고 연출 시작
CHASE      목표를 추격하고 경로를 예측
SEARCH     시야를 잃은 마지막 위치 주변 수색
CATCH      접촉과 서버 판정
RUSH_GATE  주문 감지 후 게이트로 전력 질주
```

`PATROL`은 디버그 폴백일 수 있으나 정상 플레이의 기본 목표가 아니다.

### 9.5 발견 연출

술래가 시야로 인간 또는 AI를 발견하면 즉시 다음을 발생시킨다.

- 술래 머리와 몸에서 경찰차 사이렌처럼 붉은 경광이 점멸한다.
- 붉은 빛은 월드의 벽과 바닥에 반사되어 방향을 알린다.
- 발견된 대상에게 무서운 경고음과 추격 사운드를 재생한다.
- 위험 반경 10m 안에서는 심장박동, 저주파, 화면 가장자리 붉은 비네트를 강화한다.
- 거리가 가까워질수록 사이렌 주기와 사운드 강도가 증가한다.
- 멀티에서는 발견된 대상에게 우선 강하게 전달하고, 가까운 팀원은 약하게 듣는다.

광과민성 보호 설정에서는 점멸 빈도와 명암을 낮추고 고정 붉은 광으로 대체한다.

### 9.6 포획

- 인간과 AI 모두 동일한 거리·시야·벽 차단 규칙을 적용한다.
- 포획은 서버 권위다.
- AI가 잡히면 제거 또는 빙결 상태가 팀 구성과 난도에 실제 영향을 준다.
- 술래가 목표를 바꾼 이유는 소리, 시선, 자막 등으로 추론 가능해야 한다.

## 10. AI 동료 — 독립 지능 모델

### 10.1 핵심 원칙

AI 동료는 플레이어 주변을 의미 없이 맴돌지 않는다. 각 AI는 자신만의 감지, 기억, 목표, 역할과 현재 계획을 가진다.

### 10.2 에이전트 데이터

각 AI 동료는 최소한 다음 상태를 유지한다.

- 현재 위치와 이동 경로
- 발견한 프롭과 확인 여부
- 마지막으로 본 술래 위치와 시간
- 팀원의 위치, 상태와 마지막 통신
- 현재 미션과 후보 목록
- 현재 행동 성향과 확률 가중치
- 현재 목표와 중단 가능 여부
- 구조 요청과 자신의 대응 판단
- 위험도와 경로 비용

### 10.3 목표 후보

```text
EXPLORE_ZONE       미확인 구역 탐색
INSPECT_CANDIDATE  후보 프롭 가까이에서 판별
REPORT_FINDING     발견 정보를 플레이어에게 전달
ASK_CLARIFICATION  설명이 모호할 때 질문
EXECUTE_MISSION    미션 오브젝트 조작
AVOID_SEEKER       술래와 위험 구역 회피
RESCUE_TEAMMATE    빙결된 팀원 구조
REGROUP            통신 또는 미션을 위해 합류
MOVE_TO_GATE       최종 탈출 준비
ESCAPE             문이 열린 뒤 탈출
```

각 프레임 무작정 목표를 바꾸지 않는다. 이벤트 발생 시 효용을 다시 계산하고 일정 시간 목표를 유지한다.

### 10.4 자율 탐색

- 판 시작 시 AI는 플레이어를 따라 도는 대신 각자의 판단으로 탐색 목표를 선택한다.
- 여러 AI가 같은 구역이나 같은 후보 프롭을 선택할 수 있다. 중앙 시스템이 역할을 강제 배분하거나 중복 행동을 금지하지 않는다.
- 목표 선택에는 개별 판단과 확률 변이를 적용하며, 결과적으로 협력하거나 우연히 겹치는 상황을 모두 정상적인 플레이로 취급한다.
- 프롭을 발견하면 기억에 저장하고 짧은 보고를 보낸다.
- 술래를 발견하면 마지막 목격 위치와 시간을 공유한다.
- 플레이어가 명확한 지시를 보내면 현재 목표의 중단 비용과 위험을 비교해 수락하거나 이유를 말한다.

### 10.5 후보 비교와 오해

AI는 `real_prop` 하나만 검사해서는 안 된다. 현재 미션의 진짜 후보와 디코이를 모두 동일한 입력으로 평가한다.

```text
후보 점수 = 외형 단서 + 쓰임새 단서 + 위치 단서
          + 플레이어가 가리킨 방향 + AI가 직접 본 정보
```

- 높은 확신: 후보로 이동하고 조사
- 중간 확신: `큰 것과 작은 것 중 어느 쪽이야?`처럼 확인 질문
- 낮은 확신: 이해하지 못했다고 알리고 발견한 후보 정보를 제공
- 잘못된 설명: 틀린 후보를 선택할 수 있음
- 플레이어는 추가 표현으로 AI를 교정할 수 있음

오해는 무작위 실패가 아니라 입력 단서의 부족에서 설명 가능하게 발생해야 한다.

### 10.6 빙결 위치 공유와 구조 인식

인간 또는 AI가 얼면 서버가 다음 구조 이벤트를 팀에 전송한다.

```json
{
  "type": "teammate_frozen",
  "targetId": "runner-2",
  "position": { "x": 4.2, "z": -8.1 },
  "remainingSeconds": 30,
  "danger": { "seekerLastSeen": { "x": 7.0, "z": -6.0 } }
}
```

AI 동료는 이벤트를 인식하고 다음을 수행한다.

1. 구조 가능 AI들이 거리, 경로, 술래 위험과 현재 미션 비용을 계산한다.
2. 각 AI는 구조, 미션 지속 또는 이동을 자신의 기억과 위험 판단으로 선택한다.
3. 둘 이상의 AI가 동시에 구조를 선택하거나 아무도 즉시 구조하지 않는 결과를 모두 허용한다.
4. 구조를 선택한 AI는 위치를 공유받아 실제 경로로 이동한다.
5. 가까이 도착하면 `땡` 행동을 서버에 요청한다.
6. 길이 막히거나 술래 때문에 실패하면 각 AI가 다음 판단 주기에 다시 평가한다.

솔로의 두 AI는 구조 요청을 각각 평가한다. 구조가 자동 성공으로 보장되지는 않으며, `E`는 긴급도를 높이는 요청이지 순간이동이나 무료 정답 버튼이 아니다.

### 10.7 AI도 위험의 대상

- AI도 술래에게 발견되고 추격당한다.
- AI도 트랩과 금기어로 얼 수 있다.
- AI가 얼면 인간 또는 다른 AI가 구조해야 한다.
- 제거된 AI가 공유한 정보는 남지만, 다른 팀원의 다음 목표는 각자 다시 판단한다.
- AI의 실수 빈도는 난도 설정과 연결하고 불공정한 랜덤 실패는 피한다.

## 11. 미션 구조 2.0

### 11.1 T1의 필수 수정

T1은 세 번 반복할 수 있지만 각 반복은 다음 중 적어도 하나가 달라야 한다.

- 후보가 있는 구역과 경로 위험
- 필요한 단서 종류: 외형, 쓰임새, 위치
- AI가 이미 알고 있는 정보
- 술래의 현재 수색 구역
- 플레이어와 AI의 거리
- 확인 질문의 필요성

세 후보는 모두 실제 AI 판단 대상이다. 디코이는 장식이 아니다.

### 11.2 월드 상호작용

- AI가 프롭을 조사하면 월드에서 명확한 손동작, 빛, 소리와 진행 피드백을 낸다.
- 틀린 후보 조사도 시간과 위치 노출 비용을 가진다.
- 플레이어가 직접 할 수 있는 행동과 AI만 가능한 판별을 분리한다.
- 미션 슬롯은 학교의 실제 구역과 출입구를 기준으로 작성하고 자동 도달성 테스트를 갖는다.

### 11.3 T2와 T3

기획 1의 T2와 T3는 핵심 T1이 후보 비교와 교정까지 완성된 뒤 도입한다.

- T2: AI와 인간이 떨어진 장소에서 동시 조작
- T3: AI만 본 정보를 금기어 없이 인간에게 전달

기능 수를 늘리기 위해 미완성 T1 위에 얹지 않는다.

## 12. 최종 주문과 탈출

### 12.1 단서

- 미션 성공 시 단서 조각을 얻는다.
- HUD는 획득한 조각을 보여줄 수 있지만 완성 주문 문장을 그대로 보여주지 않는다.
- 단서에는 순서, 기호, 위치 또는 관계가 있어 조합 과정이 필요하다.
- 실패한 조사나 제거된 AI 때문에 일부 정보가 손실될 수 있으나, 판이 영구 교착되지는 않아야 한다.

### 12.2 주문 완성

- 플레이어가 게이트 앞에서 단서를 보고 스스로 주문을 구성한다.
- 멀티에서는 참가자들이 각자 가진 정보를 합쳐야 한다.
- 퍼지 매칭은 발음 오류를 허용하지만 잘못된 순서와 무관한 문장을 자동 성공시키지 않는다.
- 틀린 주문도 술래가 들으며 위험 비용이 발생한다.

### 12.3 탈출

- 성공한 주문은 게이트를 열고 술래를 `RUSH_GATE`로 전환한다.
- AI 동료도 각자 게이트로 이동하고 탈출 판정을 받는다.
- 누가 탈출했고 누가 남았는지가 결과에 반영된다.
- 문 밖 센서를 실제로 통과해야 탈출이다.

## 13. 맵, 조명과 가독성

- 플레이어는 전방 손전등으로 길을 확인한다.
- 캐릭터 발과 물리 바닥은 일치해야 한다.
- 미션 프롭은 거대한 맵의 실제 교실, 체육관, 운동장, 놀이터와 후문 구역에 배치한다.
- 랜드마크, 표지판, 색온도와 환경음으로 현재 구역을 구분한다.
- 지나치게 어두워 길을 못 찾는 것과 의도적인 공포 시야 제한을 구분한다.
- 카메라는 벽과 천장을 관통하지 않도록 충돌 보정을 갖는다.
- 로딩 중에는 빈 검은 화면 대신 진행 상태와 조작 팁을 보여준다.

## 14. 사운드 원칙

사운드는 결과 알림이 아니라 정보 채널이다.

- 학교 환경음: 형광등, 바람, 먼 교실 소리
- 플레이어와 AI 발소리
- 술래의 방향성 있는 발소리와 도발음
- 시야 발견 시 붉은 경광과 동기화된 사이렌
- 빙결 균열음과 구조 `땡`
- 게이트 주문과 개방 클라이맥스
- 거리, 벽, 층에 따른 감쇠

중요 정보는 색, 소리, 자막 중 두 가지 이상으로 전달한다.

## 15. 난도와 플레이 시간

목표 플레이 시간은 기획 1과 동일하게 솔로 3~5분이다.

시간을 맞추기 위한 무반응 대기나 강제 지연은 금지한다. 다음 플레이로 시간을 구성한다.

- 후보 탐색과 AI 확인 질문
- 술래를 피한 이동 경로 선택
- 구조 담당과 위험 판단
- 틀린 후보 또는 주문의 복구
- 최종 게이트 추격

난도 설정은 다음을 조절한다.

- 술래 감지 거리와 추격 속도
- AI 판단 확신도 기준
- 구조 제한시간
- 프롭 후보 유사도
- 개인 금기어 수
- 붉은 경광·공포 연출 강도는 접근성과 별도 설정

멀티는 문서와 상태 계약을 먼저 설계하되, 솔로 핵심 AI 루프가 기능 데모 상태인 채로 네트워크 규모만 늘리지 않는다.

## 18. 완료 조건

### 시작 경험

- 시작 화면에 게임 시작, 설정, 나가기가 있다.
- 게임 시작 후 솔로/멀티를 선택할 수 있다.
- 솔로에서 캐릭터 선택과 말하기 질의응답을 거친다.
- 멀티에서 방 생성·참가·준비·캐릭터 선택이 가능하다.

### 술래

- 정상 플레이에서 고정 순찰이 기본 목표가 아니다.
- 인간과 AI를 모두 감지하고 추격한다.
- 시야 발견 시 무서운 소리와 붉은 경광이 즉시 발생한다.
- 목표를 놓치면 마지막 위치를 수색한다.
- 포획은 벽과 거리 검사를 포함한 서버 권위다.

### AI 동료

- 플레이어 주변 공전을 기본 행동으로 사용하지 않는다.
- 솔로에서는 두 AI 동료가 각각 독립된 상태와 판단 주기를 가진다.
- 독립적으로 탐색, 조사, 보고와 미션을 수행한다.
- 같은 구역·후보 선택을 허용하며 강제 역할 분담이나 중복 방지 규칙을 두지 않는다.
- 모든 후보를 비교하고 확신도에 따라 행동 또는 질문한다.
- 빙결 이벤트의 위치를 공유받고 구조 담당을 결정한다.
- AI도 술래와 트랩의 위험 대상이다.

### 핵심 게임성

- 같은 입력이 항상 정답 프롭 직행으로 끝나지 않는다.
- 틀린 이해와 교정이 플레이 가능한 상태로 존재한다.
- 최종 주문 답안이 HUD에 그대로 표시되지 않는다.
- 대기 시간이 아니라 판단과 행동으로 솔로 한 판이 3~5분을 형성한다.
- 플레이어가 AI를 제거하면 게임의 핵심 루프가 성립하지 않는다.

## 19. 매 작업 교차 감사 체크리스트

### 기획 1로 돌아가 확인

- [ ] 말하면 위험한가?
- [ ] 금기어가 빙결과 추격으로 이어지는가?
- [ ] AI 협동이 필수인가?
- [ ] 단서를 모아 주문하고 실제 문을 통과하는가?

### 기획 2로 돌아와 확인

- [ ] 시작 화면과 선택 흐름이 명확한가?
- [ ] AI가 후보를 비교하고 오해·질문·교정을 만드는가?
- [ ] 술래가 인간과 AI를 능동적으로 사냥하는가?
- [ ] 발견 상태가 사이렌과 붉은 빛으로 체감되는가?
- [ ] AI 동료가 독립 목표를 수행하는가?
- [ ] 빙결 위치 공유와 구조 담당 선택이 있는가?
- [ ] 최종 주문이 정답 읽기가 아닌가?
- [ ] 기능이 아니라 실제 선택과 결과가 생겼는가?
