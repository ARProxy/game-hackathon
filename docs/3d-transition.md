# 2.5D → 3D 전환 기록

> 작성일: 2026-08-03
> 상태: 진행 중

---

## 전환 결정 배경

프로토타입을 직접 플레이해보니 2.5D 쿼터뷰의 근본적 한계가 드러남:

1. **위에서 내려다보면 벽 뒤가 보임** — 숨바꼭질에서 "숨기"가 성립하지 않음
2. **Fog를 넣어도 벽이 시야를 가리지 않음** — 거리 기반 Fog는 장애물 차단이 아님
3. **높낮이/수직 구조가 의미 없음** — 위에서 보면 다 보임
4. **코너를 돌 때 긴장이 없음** — 항상 전체가 보이니까

## 전환 범위

이미 3D로 구축되어 있어서 변경이 적음:
- 맵, 구조물, 물리(rapier) → 그대로
- 직교 카메라 → **원근 카메라 (perspective)**
- CameraFollow → **ThirdPersonCamera** (플레이어 뒤 3인칭)
- 마우스로 시점 회전 (Pointer Lock)

## 듀얼 카메라 모드

개발 완료 전까지 2가지 뷰를 유지:
- **Tab 키**로 전환
- **CCTV 모드**: OrbitControls, 전체 맵 확인용 (개발/디버깅)
- **3D 모드**: ThirdPersonCamera, 실제 게임 시점

## 의사결정 (ADR 추가)

### ADR: 2.5D → 3D 전환

**결정**: 2.5D 쿼터뷰를 폐기하고 3D 3인칭으로 전환한다.

**왜**: 이 게임은 숨바꼭질이다. 숨바꼭질에서 가장 중요한 건 "벽 뒤에 뭐가 있는지 모르는 것"이다. 2.5D에서는 이것이 구조적으로 불가능하다. Fog는 거리만 제한하지, 장애물 뒤를 가리지 않는다. 3D 3인칭이면 벽이 실제로 시야를 차단하고, 코너를 돌 때 긴장이 생기고, 위/아래로 숨는 전략이 가능해진다.

**트레이드오프**:
- UI 오버레이(HUD, 자막)는 그대로 React DOM이라 영향 없음
- 2.5D에서의 "맵 전체 가독성"을 잃음 → CCTV 모드로 보완 (개발용)
- 이동 방향이 카메라 기준이 되어야 함 → 추가 구현 필요
- 기획서의 "2.5D 쿼터뷰" 명시와 충돌 → 기획서 업데이트 필요
