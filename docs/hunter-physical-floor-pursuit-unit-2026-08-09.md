# 술래 실제 층간 추격 단위

> 작업일: 2026-08-09  
> 기준: `game-design-v3.md`, `game-design-v4.md`  
> 범위: 주 술래·차단 술래의 계단 및 출입문 경로, 서버 포획 권위, 클라이언트 이동 표현

## 문제

진행 단계가 바뀌면 서버가 술래를 새 층의 고정 슬롯으로 즉시 옮겼다. 플레이어에게는 술래가 문 앞에 멈추거나 갑자기 등장하는 것으로 보였으며, 화면에서 계단 이동을 연출하더라도 서버가 먼저 도착해 포획하는 불공정이 생길 수 있었다.

## 경로 선택

- 술래는 현재 층과 활성 미션 층 사이의 경로를 `verticalMapContract.json`에서 탐색한다.
- 소리·빙결 신호가 유효하면 신호 발생 층을 우선 목적지로 사용한다.
- 한 층 사이에 서쪽·동쪽 계단이 모두 있으면 현재 위치에서 가까운 입구를 선택한다.
- 여러 층을 이동할 때는 한 번에 목적지로 바꾸지 않고 인접 층 경로를 하나씩 진행한다.
- 주 술래와 차단 술래 모두 같은 계약을 사용한다.

## 서버 권위

- 단계 전환 시 술래 고정 슬롯 순간이동을 제거했다.
- 술래가 작성된 계단·문 입구까지 서버 내비게이션으로 이동한 뒤에만 층 변경 이벤트가 발생한다.
- 이벤트는 actor, 경로 ID, 서·동 경로, 이동 방향, 이동 종류와 계약 시간을 포함한다.
- 작성 경로를 이동하는 3.6초 동안 서버의 다음 이동과 포획 판정을 잠근다.
- 일시정지 시간은 이동 완료 시각에도 더해지므로 메뉴를 연 동안 추격 시간이 흐르지 않는다.

## 플레이 표현

- 클라이언트는 술래의 이전 층, 도착 층과 서버 경로 정보를 대조해 같은 작성 경로를 재생한다.
- 경로 전체 길이를 기준으로 보간해 디딤판·중간참·출구를 연속 통과한다.
- 이동 중 높이와 바라보는 방향을 경로 접선에 맞춘다.
- 두 번째 술래는 별도 차선 오프셋을 사용해 계단에서 겹치지 않는다.

## 검증

- 주 술래가 입구에 닿기 전에는 서버 층이 바뀌지 않는다.
- 동쪽 계단 가까이에 있는 술래가 서쪽 계단으로 우회하지 않는다.
- 이동 잠금 중 포획은 거부되고, 계약 시간이 끝난 뒤 다시 허용된다.
- 주 술래·차단 술래 이벤트와 기존 WebSocket 진행 회귀를 검증했다.
