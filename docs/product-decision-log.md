# 사용자 질문 기반 제품 의사결정 기록

> 작성일: 2026-08-06  
> 목적: 사용자 질문이 어떤 문제를 드러냈고, 분석을 거쳐 어떤 기획·구현 결정으로 이어졌는지 추적한다.  
> 정본 관계: 핵심 규칙은 `game-design.md`, 현재 목표는 `game-design-v2.md`, 프롭·미션 상세는 `mission-discovery-contract.md`가 우선한다.

## 기록 원칙

- 질문을 단순 요청 목록이 아니라 제품 가설을 검증하는 입력으로 취급한다.
- `결정`과 `구현 완료`를 구분한다. 문서에 확정됐지만 코드에 없는 기능을 완료로 표시하지 않는다.
- 사용자가 명시적으로 제외한 규칙은 다시 암묵적으로 도입하지 않는다.
- 새 결정이 기획 1의 금기어·빙결·AI 협동·최종 주문을 훼손하는지 먼저 검사한다.
- 구현 편의를 이유로 사용자 결정의 의미를 축소하지 않는다.

## 의사결정 흐름 요약

```text
“이게 정말 게임인가?”
→ 기능 데모와 실제 플레이 경험의 차이 감사
→ 시작·선택·AI 자율성·능동 술래 강화

“맵이 안 보이고 공간 비율이 이상하다”
→ 조명·손전등·바닥 정렬·실측 스케일 계약
→ 가구와 환경을 실제 사람 크기로 교정

“문도 없고 맵도 필요하다”
→ 정적 문짝을 물리 자동문으로 전환
→ 팀 정보 중심 미니맵 추가

“솔로에 AI 동료가 더 있어야 하지 않나?”
→ 인간 1 + 독립 AI 2 + 술래 1로 개정
→ 술래 위치는 미니맵에서 제거, 동료 위치는 공개

“AI가 반드시 역할을 나눠야 하나?”
→ 강제 분담·중복 방지 폐기
→ 같은 구역·프롭·구조 목표 선택도 독립 판단 결과로 허용

“프롭이 지금 무슨 쓸모가 있나?”
→ 정답 토큰 구조의 한계 확인
→ 랜덤 메모 단서와 숨겨진 미션지의 정보 매개체로 재정의

“미션 3개 이후 무엇이 달라지는가?”
→ 술래 광분, 랜덤 탈출구, 전역 빛기둥, 최종 주문 추격으로 클라이맥스 재설계
```

## 질문과 결정 상세

### 1. 완주 가능한 기능이 실제 게임인가

사용자 질문 취지:

> 코드를 A–Z로 보고 이것이 정말 게임인지 의문점을 찾자.

확인한 문제:

- 온보딩부터 결과까지 연결돼도 플레이어의 선택과 결과가 약하면 기능 데모에 머문다.
- AI가 정답으로 직행하고 술래가 수동적으로 순찰하면 AI 게임의 핵심 판타지가 체감되지 않는다.
- 거대한 학교가 미션 동선에 충분히 쓰이지 않았다.

결정:

- 기획 2를 만들어 `선택 → 결과 → 피드백 → 재판단`을 완료 기준으로 삼았다.
- 시작 화면, 모드 선택, 캐릭터 선택, 음성 질의응답을 게임 전 흐름으로 분리했다.
- 술래는 인간과 AI를 계속 사냥하는 능동 모델, AI 동료는 독립 목표 모델로 개정했다.

상태: 핵심 시작 흐름과 단일 AI·술래 모델은 구현됨. AI 2명과 새 미션 구조는 미구현.

### 2. 맵이 너무 어둡고 캐릭터가 땅에 박힌다

사용자 질문 취지:

> 플레이어는 손전등을 들고 다니고, 바닥과 캐릭터 발 위치가 같아야 한다.

확인한 문제:

- 공포 분위기와 길을 읽지 못하는 저가독성 상태가 구분되지 않았다.
- 캐릭터 비주얼 원점과 물리 캡슐 바닥의 차이로 접지감이 틀어졌다.

결정:

- 전방 손전등을 기본 정보 도구로 둔다.
- 캐릭터 모델 원점을 발바닥으로 정의하고 물리 바디 오프셋을 보정한다.
- CCTV는 공포 노출과 분리된 개발용 판독 조명을 사용한다.
- 실내는 손전등만 의존하지 않고 천장등과 공간별 색온도를 갖는다.

상태: 구현됨. 공간별 조명과 외벽 재료는 지속 개선 중.

### 3. 이동과 프롭이 흔들려 보인다

사용자 질문 취지:

> 앞으로 가는 것이 어색하고 이동할 때마다 프롭이 흔들리는 것 같다.

확인한 문제:

- 카메라와 플레이어가 서로 다른 물리·비주얼 위치를 즉시 따라가며 미세 진동이 확대됐다.
- 걸음 피드백이 없어 속도 변화가 미끄러짐처럼 느껴졌다.

결정:

- 물리 위치와 비주얼 위치를 분리하고 감쇠 추종을 사용한다.
- 카메라 충돌과 추종도 물리 컨텍스트 안에서 안정화한다.
- 보행 애니메이션과 발소리를 실제 이동량에 연결한다.

상태: 구현됨.

### 4. 학교가 검고 비율이 이상하다

사용자 질문 취지:

> 건물 내부 조명이 없고 외벽이 검으며, 에셋 크기와 비율이 공간에 맞지 않는다.

확인한 문제:

- 학생 책상 상판이 약 0.38m로 너무 낮고 의자는 통짜리 상자였다.
- 기존 GLB는 원본 단위가 현실 미터가 아니어서 스케일 1 배치 시 벤치와 침대 등이 절반 크기였다.

결정:

- `1 Three unit = 1m`, 플레이어 키 1.7m를 월드 계약으로 고정했다.
- GLB는 바운딩 박스를 측정한 뒤 목표 실측 크기로 정규화한다.
- 반복 가구는 실제 치수의 다부품 인스턴스로 만든다.
- 공식 CC0이면서 현재 저폴리곤 스타일과 맞는 에셋만 선별한다.

상태: 본관 핵심 가구 1차 교정 완료. 외벽·운동장·체육관은 진행 예정.

### 5. 학교 내부에 열고 닫는 문과 우측 상단 맵이 필요하다

사용자 질문 취지:

> 학교 내부에 열고 닫는 문이 없고 오른쪽 상단에 맵이 필요하다.

확인한 문제:

- 기존 갈색 문짝은 문처럼 보이지만 정적 벽 콜라이더라 실제로 열리지 않았다.
- 학교 규모가 커졌지만 현재 위치와 팀 상태를 읽는 탐색 도구가 없었다.

결정:

- `E`가 구조·조사와 충돌하므로 본관 문은 같은 층 반경 2.15m에서 자동 개폐한다.
- 문은 실제 회전축과 키네마틱 물리 충돌체를 가진다.
- 미니맵은 주요 구역, 현재 층, 자신, 동료, 활성 탈출구를 표시한다.

상태: 자동문 8개와 미니맵 구현 완료.

### 6. 미니맵 정보와 솔로 인원

사용자 질문 취지:

> 술래 위치는 안 보여도 동료 위치는 보여야 하며 솔로는 최소 세 도망자여야 한다.

확인한 문제:

- 당시 기획 1에는 `인간 1 + AI 동료 1 + 술래 1`이 전체 3명으로 적혀 있었다.
- 초기 미니맵은 술래 위치까지 표시해 공포와 추적 판단을 무력화했다.

결정:

- 솔로 도망자 팀을 `인간 1 + AI 동료 2`, 별도 AI 술래 1명으로 개정한다.
- 미니맵은 AI 동료 위치를 항상 표시하고 술래 위치는 표시하지 않는다.
- 술래 정보는 발소리, 사이렌, 붉은 경광, 마지막 목격 보고로만 전달한다.

상태: 문서 계약과 술래 미니맵 제거 완료. 두 번째 AI의 서버·클라이언트 구현은 미완료.

### 7. AI 동료의 행동을 강제 분담하지 않는다

사용자 질문 취지:

> 서로 다른 후보나 구역을 나눠 탐색하는 규칙과 동일 프롭 중복 방지를 빼고 AI 지능과 랜덤성에 맡긴다.

검토한 대안:

- 중앙 감독기가 두 AI에게 서로 다른 구역과 역할을 강제 배정한다.
- 이미 다른 AI가 선택한 프롭에 잠금을 걸어 중복 접근을 막는다.

결정:

- 두 대안을 모두 폐기한다.
- 각 AI는 자신의 기억, 위험도, 목표 효용과 확률 변이로 독립 판단한다.
- 같은 구역, 같은 프롭, 같은 구조 대상을 동시에 선택할 수 있다.
- 우연히 효율적인 협력이 생기거나 비효율적으로 겹치는 결과 모두 정상적인 플레이다.

상태: 기획 계약 완료. 다중 AI 구현 시 반드시 유지해야 함.

### 8. 현재 프롭은 무용지물인가

사용자 질문 취지:

> 프롭이 지금 상태에서 무엇을 할 수 있으며 사실상 무용지물 아닌가?

확인한 현재 동작:

- 프롭은 정답 1개와 디코이 2개의 빛나는 도형이다.
- 인간은 조사할 수 없고 AI만 서버에 `inspect_prop`을 요청할 수 있다.
- 정답이면 주문 조각을 얻고, 오답이면 메시지를 출력하며, 조사 후 월드에서 삭제된다.
- 집기, 운반, 장치 사용, 환경 변화와 연결되지 않는다.

판단:

- 서버 판정 기능은 있으나 플레이어에게는 AI 후보 비교용 디버그 토큰에 가깝다.
- 프롭 자체가 탐색, 추론, 협동과 월드 변화를 만들지 못한다.

결정:

- 프롭을 미션 정답에서 미션지 단서를 담은 정보 컨테이너로 재정의한다.
- 인간과 AI 모두 조사할 수 있게 한다.
- 조사한 프롭은 삭제하지 않고 읽은 흔적과 팀 기록을 남긴다.

상태: 계약 완료, 구현 미완료.

### 9. 랜덤 프롭 메모와 숨겨진 미션지

사용자 질문 취지:

> 프롭이 다양한 장소에 랜덤 배정되고, 조사하면 “미션지는 학교 2층 교실 쪽에 있지 않을까…” 같은 메모를 제공한다. AI가 보면 음성으로 말한다.

결정:

- 프롭은 실제 공간 문법에 맞는 다수 슬롯 중 라운드 시드로 배치한다.
- 메모는 정확한 좌표 대신 층, 공간 종류, 랜드마크, 방향 중 1~2개만 알려준다.
- 인간 조사 시 HUD 메모와 팀 기록, AI 조사 시 AI 기억과 음성·자막 보고를 사용한다.
- 메모는 탐색 범위를 좁힐 뿐 AI에게 정답 좌표를 주지 않는다.
- 한 프롭을 놓쳐도 교착되지 않도록 같은 미션지의 단서를 복수 프롭에 둘 수 있다.

상태: `mission-discovery-contract.md`에 확정, 구현 미완료.

### 10. 미션 수, 유형과 숨김

사용자 질문 취지:

> 총 인원수에 따라 미션지는 3개이며 잘 숨겨져 있다. 협동 또는 혼자 깨는 미션이고 확률은 랜덤이다.

해석:

- 미션 수는 활성 도망자 수와 같게 둔다.
- 솔로 기본 도망자는 3명이므로 미션지는 3개다.
- 도중 탈락으로 미션 수가 줄면 난도가 역으로 낮아지므로 라운드 시작 후 수를 고정한다.

결정:

- 미션지는 강한 발광 대신 근거리 형태, 미세한 소리, 비정상적 배치로 숨긴다.
- 메모 획득 후에도 정확한 점이 아닌 탐색 범위만 미니맵에 표시한다.
- 미션 템플릿은 `solo`와 `coop` 태그를 가진다.
- 특정 비율이나 순서를 강제하지 않고 호환 가능한 템플릿 중 시드 기반 무작위로 뽑는다.

상태: 계약 완료, 미션 템플릿 구현 미완료.

### 11. 세 미션 완료 후 광분과 탈출

사용자 질문 취지:

> 세 미션을 깨면 술래가 광분해 빨라지고 빨간 빛을 낸다. 세 도망자는 랜덤 탈출구를 찾아야 하며 빛이 하늘까지 뻗어 어디서든 보여야 한다.

기획 1과의 충돌 검사:

- 기획 1의 핵심 클라이맥스는 단서를 조합한 최종 주문이다.
- 새 제안은 주문 제거를 명시하지 않았으므로 최종 주문을 탈출구 개방 단계로 유지한다.

결정:

- 세 번째 미션 성공 순간 서버가 술래 `ENRAGED`를 선언한다.
- 초기 튜닝 기준 속도는 기본의 1.35배이며 붉은 경광, 사이렌, HUD 경고를 함께 낸다.
- 동시에 사전 검증된 랜덤 탈출구 하나에서 하늘까지 빛기둥을 켠다.
- 탈출구는 그전까지 미니맵과 월드에서 비공개다.
- 도망자들은 빛기둥을 보고 집결하고 최종 주문으로 문을 연 뒤 실제 센서를 통과한다.

상태: 계약 완료. 기존 랜덤 게이트와 주문 코드를 확장해야 함.

## 명시적으로 폐기된 규칙

- AI 동료에게 서로 다른 구역을 강제 배정
- 이미 선택된 프롭을 다른 AI가 선택하지 못하게 잠금
- 미니맵에 술래의 실시간 위치 표시
- 프롭을 조사 즉시 삭제
- 프롭을 세 번 고르는 반복만으로 전체 미션 구성
- 세 미션 완료 즉시 자동 승리 또는 주문 없는 자동 탈출

## 현재 구현 격차와 다음 순서

1. 서버의 단일 `partner` 상태를 독립 AI 동료 2명으로 일반화한다.
2. 프롭 슬롯·메모·조사 기록을 서버 권위 라운드 데이터로 만든다.
3. 인간 `E` 조사와 AI 조사·음성 보고를 동일 이벤트 계약에 연결한다.
4. 숨겨진 미션지 3개와 솔로/협동 템플릿 실행기를 만든다.
5. 세 번째 완료 이벤트에 술래 광분과 붉은 연출을 연결한다.
6. 랜덤 탈출구 빛기둥과 최종 주문·개별 탈출을 연결한다.
7. 시드 재현, 도달성, 교착 방지, AI 중복 선택 허용을 자동 테스트한다.

## 2026-08-06 구현 기록: 솔로 3인 도망자 팀

- 서버 예약 actor를 `partner`, `partner-2`, `seeker`로 확장했다.
- 두 AI는 기억, 사용자 명령, 구조 요청, 목표 유지 시간, 술래 목격 기억을 공유하지 않는다.
- 중앙 분배기는 두 AI의 목표 중복을 제거하지 않는다. 같은 프롭을 동시에 고르는 결과도 테스트로 허용했다.
- 인간의 발화 명령과 구조 요청은 두 AI 모두가 받되, 이후 행동 판단은 각자의 상태와 위치에서 수행한다.
- AI 한 명이 빙결 또는 탈락해도 인간과 다른 AI가 살아 있으면 라운드를 계속한다. 모든 도망자가 행동 불능일 때만 패배한다.
- 클라이언트는 두 캐릭터, 두 서버 위치, 두 미니맵 마커와 동료별 빙결 구조 안내를 표시한다.
- 술래 위치는 기존 결정대로 미니맵에 노출하지 않는다.

검증: 서버 253개 테스트, 클라이언트 프로덕션 빌드와 린트 통과. 린트에는 기존 Fast Refresh 경고만 남아 있다.
