# 전 층 실제 계단·출입문 이동 단위

> 작업일: 2026-08-09  
> 기준: `game-design-v3.md`, `game-design-v4.md`  
> 범위: 3층↔2층, 2층↔1층, 1층↔지하, 1층↔운동장 및 AI 동료의 동일 경로 표현

## 문제

옥상↔3층만 실제 계단을 걸었고 나머지는 문 앞에서 E를 누르면 목적 층 좌표로 바뀌었다. 지하로 연결되는 실제 계단 구조물도 없었다. 이 때문에 맵 외형, 서버 층 권위, 플레이 체감이 서로 달랐다.

## 구조 변경

- 기존 F3↔F2, F2↔F1의 북서·남동 스위치백 계단 경로를 월드 계약에 명시했다.
- B1↔F1 북서 계단을 실제 디딤판, 두 경사로, 중간참, 상부참, 난간과 구조 거더로 추가했다.
- F1 북서 슬래브에 계단 보이드를 열고 추락 방지 난간을 연결했다.
- F1↔운동장은 현관 안쪽과 바깥쪽의 실제 문 통과 경계를 사용한다.
- 구조 변경 뒤 서버 충돌 계약을 같은 맵 데이터에서 다시 생성했다.

## 서버 권위 변경

- 문 앞 좌표에서는 층 이동을 거부한다.
- actor가 실제 경로의 반대편 끝점 1.35m 안에 도착해야 층 권위를 전환한다.
- 전환 이벤트는 `traversal`, `path_id`, `direction`을 함께 제공한다.
- 닫힌 층, 아직 열리지 않은 층, 살아 있지 않은 도망자의 이동은 계속 거부한다.
- 이전 층 폐쇄는 모든 살아 있거나 빙결된 도망자가 실제 경계를 건넌 뒤에만 일어난다.

## 플레이어와 AI

- 플레이어는 계단 입구 안내를 보고 문을 열어 실제 경사로를 끝까지 걷는다.
- E 키는 층간 순간이동을 더 이상 발생시키지 않는다.
- AI는 플레이어의 층 변경 이벤트에서 작성된 경로와 방향을 받는다.
- AI는 먼저 해당 계단 입구까지 서버 내비게이션으로 이동한다.
- 서버 승인 후 클라이언트는 같은 작성 경로를 따라 AI의 높이·방향·보행을 연속 재생한다.
- 두 AI는 서로 다른 가로 오프셋을 사용해 계단에서 겹치지 않는다.

## 회귀 계약

- 모든 작성 경로의 첫점과 끝점이 서버 층 경계 슬롯과 정확히 일치한다.
- 문 앞 순간이동 시도는 테스트에서 거부된다.
- 동쪽·서쪽 양 계단과 왕복 이동을 검증한다.
- 옥상→운동장 및 옥상→지하 자동 플레이가 실제 도착 경계를 사용한다.
- compact school 구조 검증은 지하 계단을 포함한 14개 경사로, 112개 계단 질량, 28개 구조 거더를 요구한다.
