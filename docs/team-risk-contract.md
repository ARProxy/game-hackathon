# 인간·AI 공통 위험, 구조와 탈출 계약

> 기획 정본: `game-design.md` 8장, `game-design-v2.md` 10.6·10.7·12.3·16장

`partner`, `seeker`는 서버 전용 예약 ID다. 인간 WebSocket 연결은 정책 위반으로 거부하며, 판 시작 시에도 각각 `ai_partner`, `seeker` 역할을 강제로 재검증한다. 같은 인간 ID의 동시 접속도 거부해 소켓 소유권과 빙결 상태가 덮어써지지 않게 한다.

## 공통 위험

- 활성 트랩은 서버가 판마다 선택하고 `game_started.active_traps`로 공개한다.
- 인간과 AI 모두 트랩 반경 1m에 진입하면 서버 권위로 빙결된다.
- AI가 안전하지 않은 발화를 하면 인간과 같은 금기어 엔진으로 판정해 빙결·위치 노출·30초 제한시간을 적용한다.
- 빙결과 구조는 대상 ID, 서버 위치, 상태와 벽 차단을 검증한다. 벽 차단 계약은 본관 1층뿐 아니라 운동장·골목의 사람 키 이상 벽과 대형 장애물도 포함한다.
- 빙결 이벤트는 남은 제한시간과 AI가 기억한 술래 마지막 위치를 포함해 구조 판단과 HUD에 사용한다.

## 상호 구조

- AI는 인간의 빙결 위치를 공유받고 위험이 낮을 때 실제 이동해 구조한다.
- AI 구조도 벽 차단을 검사하며, 팀 전원이 얼면 제한시간을 기다리지 않고 즉시 패배한다.
- 인간은 빙결된 AI의 2m 안에서 `E`를 눌러 구조한다. 멀리서 요청하거나 벽 너머에서 구조할 수 없다.
- AI가 제한시간 내 구조되지 못해 제거되면, AI 전용 판별이 필요한 솔로 미션은 실패로 종료한다.

## 개별 탈출

- 게이트 개방 뒤 AI도 서버 위치로 게이트까지 이동하고 실제 근접 판정을 받아 `escaped` 상태가 된다.
- 술래 접촉과 탈출이 겹치면 포획을 우선한다.
- 인간의 탈출로 판이 끝날 때 AI의 `escaped`, `alive/frozen`, `eliminated` 상태를 결과 payload와 정산 화면에 표시한다.
