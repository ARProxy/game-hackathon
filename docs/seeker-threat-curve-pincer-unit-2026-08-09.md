# 술래 위협 곡선과 협공 안정화 작업 기록

> 작업일: 2026-08-09  
> 작업 단위: 3층 등장·제한 추격, 2층 완전 추격, 1층 차단자 협공  
> 상태: 구현·자동 검증 완료

## 문제

- `limited_hunt` 상태가 선언만 되어 있고 실제 진행에서는 3층 전체가 `omen`으로 유지됐다.
- 옥상과 3층 전반에도 술래의 감지·소리 기억·포획 요청을 서버가 별도로 차단하지 않았다.
- 1층 차단자가 보내는 `BLOCK`, `GUARD`, `PATROL`을 클라이언트 타입과 속도표가 몰라 표시 속도가 `NaN`이 될 수 있었다.
- 차단자의 기본 순찰 좌표가 월드 좌표의 부호를 뒤집어 만들어져 ㅁ자 학교 밖을 목표로 삼을 수 있었다.
- 얼어 있는 도망자 경계 시작 시각이 `0`으로 남아 경계 상태가 사실상 실행되지 않았다.
- 구역 공유 주석과 달리 계산된 측면 목표를 추격자에게 전달해 정밀 위치 공유에 가까웠다.

## 구현

- 현재 위협을 `effective_seeker_threat` 한 곳에서 계산한다.
- 옥상은 감지·소리 수신·포획 판정을 비활성화한다.
- 3층 미션 장치 활성화를 후반 진입 사건으로 사용해 `omen → limited_hunt`를 전환한다.
- 제한 추격은 직접 목격과 유효 소리에는 반응하지만 정보가 끊기면 임의 순찰 대신 현재 위치에서 대기한다.
- 2층은 완전 추격, 1층은 두 명 협공, 파이널은 광분이라는 기존 단계 계약을 유지한다.
- 서버 포획 판정은 위협 상태와 활성 술래 수를 함께 검사한다.
- 위협 변경을 WebSocket으로 즉시 전파하고 HUD에 현재 대응법을 표시한다.
- 차단자 상태를 클라이언트 이동 속도표에 추가하고, 차단 상태에서는 포획 요청을 보내지 않는다.
- 추격자는 붉은 경광·사이렌, 차단자는 정적인 백색 손전등으로 구분한다.
- 차단자 측면·순찰·공유 위치를 현재 층의 공용 링 내비게이션 노드로 양자화한다.
- 경계 타이머는 특정 빙결 대상의 첫 경계 순간부터 시작하고 8초 뒤 재개하지 않는다.

## 기획 교차 확인

- 3층 초반: 실루엣과 발소리만 있는 암시
- 3층 후반: 큰 소리·직접 목격 기반의 짧은 제한 추격
- 2층: 인간과 AI를 대상으로 한 완전 추격
- 1층: 청각 추격자 + 시야 차단자의 역할 분리
- 차단자 발견 정보는 정확한 좌표가 아닌 구역 수준으로 공유
- 파이널: 시간 강화는 멈추고 진입 시점 광분 난도를 유지
