# Batch 001 — 구조 정본과 교실 5개 서명

## 문제

- 특별실을 시드마다 독립적으로 섞어 과학실-준비실 등 기능 suite가 분리됐다.
- 일반교실 10곳이 같은 4×5 격자였고, 차이는 파손 상태뿐이었다.
- 프로그램실 42곳 중 정상 상태가 18곳뿐이라 정상 학교보다 난장이 먼저 읽혔다.
- 기존 검증은 배열 개수만 검사해 zoning, 교실 다양성, 서버 충돌 동기화를 보장하지 못했다.

## 결정

- 특별실 셔플을 제거하고 고정 zoning을 정본으로 삼았다.
- 일반교실에 `rows`, `pods`, `exam`, `horseshoe`, `project` 레이아웃을 명시했다.
- 칠판 기준 `(u, v)` 방 로컬 좌표를 도입해 윙 방향과 무관하게 가구가 함께 회전하도록 했다.
- 학생 책상을 0.72×0.48m로 교정하고, 낮은 가구가 양쪽 문 진입 구역을 침범하면 생성하지 않는다.
- 교실은 정상 상태로 보존하고, 전역 파손 quota를 12/42로 줄여 정상률을 71.4%로 맞췄다.

## 자동 검증

- 방 80, 문 122, 승강기 2 유지.
- 교실 10곳과 레이아웃 5종 유지, 각 레이아웃 2회 등장.
- 레이아웃별 로컬 footprint signature 5종이 서로 다름.
- 교실 가구의 방 경계 및 문 진입 구역 침범 0.
- 과학실-준비실, 음악실-준비실, 방송실-준비실 중심 거리 각각 8.1m 이하.
- seed 0/1 사이 방 ID·층·중심 좌표 불변.
- 생성된 서버 벽 충돌 JSON과 클라이언트 구조물 deep equality.

## 남은 위험

- 중심 거리 8.1m는 실제 문-복도 최단 경로 검증으로 강화해야 한다.
- 학생 책상은 아직 시각 전용이라 술래 시야와 이동 판단을 바꾸지 않는다.
- 레거시 wrapper, 미니맵, 미션 슬롯은 v4 방 정본과 완전히 통합되지 않았다.
- 문 122개 갱신과 HMR/StrictMode 조합은 Rapier 오류 재현 가능성을 별도 배치에서 다뤄야 한다.
