# Batch 008 — 1층 행정 4실의 공간 문법 분리

## 문제

교무실·행정실·교장실·상담실이 모두 2×3 사무용 책상, 파티션, 캐비닛, 복사기를 공유했다. 파손 상태만 달라 실제 플레이에서는 네 방이 같은 방처럼 보였다. 작은 가구는 시각물만 있고 Rapier와 서버 시야 계약에는 없는 경우도 있었다. 임의 seed에서는 필수 전화·캐비닛이 붕괴공에 의해 삭제될 수 있었다.

## 변경

- 교무실: 중앙 당직 전화, 세 교사 pod, 출결판, 우편함 벽으로 큰 공동 업무실을 만들었다.
- 행정실: 방문자 전실과 기록 업무 구역을 긴 민원 카운터로 분리하고 미션을 실제 기록 캐비닛에 결속했다.
- 교장실: 중앙 붕괴공을 가구로 덮지 않고 동측 안전 lane, 파손 desk, 열쇠함, 초상으로 구성했다.
- 상담실: 소파·상담 의자·원형 카드 테이블·감정 보드로 저밀도 대화 공간을 만들었다.
- 기존 프롭/미션 좌표를 각 landmark의 실제 표면으로 옮겼다.
- `forceCollider`를 데이터 타입, Rapier 구조 판정, 서버 collision export가 모두 소비하도록 추가했다.
- 대표 가구마다 숨은 저상 collider를 두고 visual과 같은 중심인지 자동 검사한다.
- 1층 붕괴실은 교장실로 고정하고 hole 좌표를 정본화해 필수 anchor가 seed에 따라 사라지지 않게 했다.

## 검증

- seed 0~199에서 파손 quota, suite, 교장실 붕괴, 교무실·행정실 필수 anchor 생존을 검사한다.
- 네 방의 고유 landmark와 강제 collider 수를 검사한다.
- 교장 desk가 붕괴공 0.40m 안전 버퍼와 겹치지 않는지 검사한다.
- seed 0 교무실 breach 내부 접근 apron을 가구 collider가 막지 않는지 검사한다.
- `npm run build`, `npm run export:collision`, `npm run verify:campus` 통과.

## 남은 위험

- 새 선택 미션은 시각 landmark만 만든 상태이며 vertical runtime에 연결하지 않았다.
- 캐비닛 미션과 행정실 인터폰 장치는 서로 다른 좌표 계약이므로 이후 통합 때 합치면 안 된다.
