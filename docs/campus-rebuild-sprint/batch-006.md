# Batch 006 — 방송 suite와 v4 트랩 정본

## 문제

방송실은 준비실 연결문이 생겼지만, 부스 유리가 충돌 없는 시각물이라 화면에서는 막히고 물리에서는 통과되는 `ghost wall`이었다. 기존 유리는 플레이어 지름과 같은 끝 여유만 남겼고, 조정 콘솔의 프롭·M01 미션 좌표도 실제 상판과 분리돼 있었다. 트랩은 런타임 JSON 12개와 맵 생성기 11개가 서로 다른 ID·좌표를 가진 이중 정본이었다. 지형 파손 quota와 문 링크의 `flip` 처리에도 오래된 값이 남아 있었다.

설계 에이전트는 방송실의 room-local 좌표와 문 접근 금지영역을 산출했고, QA 에이전트는 seed 0~255 suite 보존, 슬롯 표면, 이중 트랩 정본과 stale quota를 독립 검증했다. 첫 유리 수정안은 1.10m 개구를 만들었지만 suite 문 접근영역을 침범했고, 강화된 검증기가 이를 실패시켰다. 파티션을 방 안쪽으로 0.50m 옮겨 반례를 제거했다.

## 변경

- 방송 조정 콘솔을 `(u=0.8, v=2.35)`에 두고 프롭·M01·델타를 같은 상판 assembly에 묶었다.
- 부스 파티션을 큰 유리와 짧은 stub으로 분리해 실제 개구 폭 1.10m를 만들었다.
- 유리 2개와 동일한 고정 collider 2개를 추가해 시각 점유와 Rapier 점유를 일치시켰다.
- 파티션을 `v=5.05`로 이동해 방송실–준비실 연결문의 캡슐 접근영역을 보존했다.
- 복도문 위에 `ON AIR` 랜드마크를 배치하고, 외벽 흡음패널과 녹음 테이블·마이크로 방송실 실루엣을 강화했다.
- 방송준비실 케이블 드럼을 suite 횡단축 밖으로 옮겼다.
- `trapContract.json`의 기존 런타임 ID 12개를 v4 실제 좌표로 이동하고, 생성기의 `TRAP_SLOTS`도 이 JSON에서 파생하도록 바꿨다.
- 생성 계약과 런타임 트랩의 ID·층·좌표가 완전히 같은지 자동 비교한다.
- 지형 파손 quota를 실제 상태 수와 비교하고, 16개 seed에서 suite 보존과 고정 quota를 검사한다.
- 문 링크 좌표 계산에 `flip`을 반영했다.
- 서버 websocket 테스트는 트랩 좌표를 하드코딩하지 않고 공통 계약에서 읽는다.
- suite 문 UI는 일반 교실 문과 구분해 `연결문`으로 표시한다.

## 검증

- `npm run export:collision`로 방송 유리 collider를 서버 충돌 계약에 반영했다.
- `npm run verify:campus` 통과: solids 2,394, visuals 5,804, 방 80개, 문 127개, 정상 상태 71.4%.
- 방송 부스 시각 파티션 2개, collider 2개, 순수 개구 폭 1.10m를 자동 검사한다.
- `npm run build` 통과.
- 서버 전체 테스트 `256 passed, 1 skipped`.

## 남은 위험

- `SchoolCampus.tsx`에는 v4의 120m와 다른 legacy `MAP_SIZE=80` 및 트랩 의미 메타데이터가 남아 있다.
- actor·gate·mission·vertical 계약이 실제 렌더 정본과 동일한지 소비 경로별 감사가 필요하다.
- 문짝 회전 sweep와 문–미션 사이 캡슐 팽창 BFS는 아직 자동화하지 않았다.
