# Batch 005 — 기능실 suite와 캡슐 진입 여유

## 문제

준비실은 본실 옆에 놓였지만 두 방을 직접 잇는 내부문이 없어 실제 suite가 아니었다. 1층 급식 구역은 급식실–조리실–배식준비실 순서라 학생 배식과 조리 작업 동선이 교차했고, 배식준비실은 조리실 가구를 그대로 복제했다. Batch 004의 문 검사는 직사각형 1.5m만 보아 플레이어 캡슐 반경과 로컬/월드 좌표 불일치를 놓칠 수 있었다.

두 검토 에이전트는 각각 공간 정체성과 실패 조건을 공격적으로 검토했다. 그 과정에서 도서실 미션 앵커가 새 중앙 서가 안에 들어간 문제, 영어실 원기둥 검증 누락, 시청각실 계단석의 문 여유 부족, suite 방에 파손 상태가 배정되는 문제를 확인했다.

## 변경

- 급식 구역을 급식실→배식준비실→조리실 순서로 고정했다.
- 배식준비실에 독립 `serving` kind와 트레이 라인·보온장·반납함 배치를 만들었다.
- 급식실은 6개 식탁과 suite측 배식대로, 조리실은 외벽 조리선·중앙 작업섬·국솥·냉장고로 분리했다.
- 급식 2개, 음악실–악기준비실, 과학실–과학준비실, 방송실–방송준비실에 폭 1.4m 개구부와 실제 `suite` 문 5개를 추가했다.
- 모든 필수 suite는 공유 경계, 동일 문 ID의 양쪽 `cells.links`, 실제 문 폭을 자동 검사한다.
- 필수 suite 방은 파손·붕괴·비움 상태 배정에서 제외해 정상 기능 관계를 보존한다.
- 문 접근 깊이에 플레이어 반경 0.4m를 추가했다. 이 강화된 규칙에 맞춰 교실 첫 줄, 영어 포드, 시청각실 계단석과 급식 가구를 재배치했다.
- 로컬/월드 좌표 역변환 일치와 `navRole`의 높이·벽 부착 조건을 검사한다.
- 도서실과 조리실의 프롭·미션·함정 앵커를 실제 새 가구 표면으로 이동했다.
- 바뀐 벽 개구부를 서버 충돌 정본에 다시 내보냈다.

## 검증

- `npm run verify:campus` 통과: 방 80개, 문 127개, 실제 suite 문 5개, 정상 상태 71.4%.
- `npm run build` 통과.
- 서버 전체 테스트 `256 passed, 1 skipped`.

## 남은 위험

- 문짝의 회전 sweep 자체와 가구 조립품 단위 overlap은 아직 자동 검사하지 않는다.
- 0.1m 격자와 캡슐 팽창 장애물을 이용한 문–미션 간 BFS 연결성 검사는 다음 배치 후보이다.
- 방송실 부스 유리는 내부 통로 표현을 더 명확히 해야 한다.
