# Batch 007 — 지하 설비실과 탈출 계약 정본

## 문제

지하의 저수조실·기계실·전기실이 같은 `machine` 장식 분기로 생성되어 방 이름만 달랐다. 일부 원통형 설비는 보이는 위치와 충돌 프록시 위치가 달라 보이지 않는 벽을 만들었다. 탈출 게이트와 트랩도 런타임 JSON, 생성 데이터, 데모가 서로 다른 좌표를 소유했다. 방송 부스의 짧은 유리 collider는 Rapier 구조물 휴리스틱에서 탈락할 수 있었다.

## 변경

- 저수조실은 2개 물탱크·매니폴드·수위계, 기계실은 4개 펌프 스키드·제어반, 전기실은 4개 배전반·UPS·고압 경고로 분리했다.
- 모든 큰 설비의 visual과 고정 collider가 같은 room-local 좌표를 가지도록 1:1 검증한다.
- 세 설비실 중앙에 폭 1.40m 서비스 통로를 예약하고 구조 collider 침범을 금지했다.
- 방송 부스 stub collider를 방 바깥 방향으로만 확장해 Rapier 최소 구조물 크기를 충족하면서 실제 1.10m 개구는 유지했다.
- 트랩의 수량·종류·위험 설명과 게이트의 이름·층·회전을 런타임 JSON 하나에서 생성하도록 변경했다.
- 데모 후문 좌표를 실제 후문 골목 좌표와 맞췄다.
- 문 cleanup zone 계산에 `flip` 방향을 반영했다.

## 검증

- `npm run export:collision`과 `npm run verify:campus` 통과.
- 설비 landmark, collider 수, 중앙 통로, visual/collider 위치 parity를 자동 검사한다.
- 런타임·생성기 트랩 전체 객체와 게이트 전체 객체의 완전 동등성을 검사한다.

## 남은 위험

- 층간 device/actor 계약은 여러 소비자가 남아 있어 별도 통합이 필요하다.
- 서버 websocket의 companion report와 game-over 메시지 순서 테스트는 이 맵 변경과 무관하게 불안정하다.
