# 실내 장소성 복구 사고 흐름

## 관찰

조명 개선으로 벽과 바닥은 읽히지만, 성능 최적화 과정에서 `Furnishings`가 비활성화되어 교실·행정실·보건실·복도가 빈 상자처럼 보인다. 기존 구현을 그대로 켜면 동일한 GLB를 수백 번 clone하고 복도 PointLight도 다시 추가하므로, 이미 해결한 draw call과 광원 병목이 재발한다.

## 판단

지금 필요한 것은 소품의 세밀한 모델링보다 방에 들어서는 순간 용도를 읽게 하는 큰 실루엣이다. 교실의 책상 열, 복도의 사물함, 행정실의 업무 책상, 보건실의 침대처럼 공간 정체성을 만드는 오브젝트를 먼저 복구한다. 충돌은 기존 `SchoolCampus`가 계속 담당하며 장식은 이동을 막지 않는다.

## 구현 계약

- 가구는 박스 기반 `InstancedMesh`로 재구성하고 색상·층 단위로 배치한다.
- 교실에는 3×3 책상과 의자, 복도에는 반복 사물함을 둔다.
- 1층에는 행정실·로비·보건실을 구분하는 고유 가구를 둔다.
- 2층과 3층은 교실 배열과 복도 가구를 유지해 층을 이동해도 빈 공간이 되지 않게 한다.
- 추가 PointLight는 만들지 않고 앞 단계의 천장등을 공유한다.
- 기존 Kenney GLB 가구 파일과 구현은 삭제하지 않는다. 장식 품질을 더 올릴 때 거리 컬링 또는 실제 GLB 인스턴싱을 적용한 뒤 선택적으로 사용한다.

## 성공 기준

교실 문을 통과했을 때 책상 배열이 즉시 보이고, 복도와 방의 시각적 차이가 손전등 없이도 드러나야 한다. 가구 추가 뒤에도 모델 clone과 PointLight 수는 늘지 않아야 하며 클라이언트 빌드와 린트가 통과해야 한다.

## 2026-08-06 현실성 재감사

### 새 관찰

- 모든 문이 접근만 하면 같은 방향으로 약 86도 회전해 플레이어 동선을 침범했다.
- 문짝 위 가로대만 있고 좌우 문틀, 레일, 유리창이 없어 완성된 학교 문으로 읽히지 않았다.
- 국내 학교 교실에서 익숙한 미닫이문보다 자동 스윙 도어에 가까워 공간 맥락과 어긋났다.
- 복도 조명은 늘었지만 교실 안쪽 책상과 칠판에는 직접광이 없어 가구 실루엣이 다시 검게 합쳐졌다.

### 개정 결정

- 교실·행정실·특별실의 문 8개를 수동 미닫이문으로 교체한다.
- 접근만으로 열지 않고 1.65m 안에서 `E`를 눌러 열고 닫는다.
- 문짝은 벽과 평행하게 1.34m 이동하며, 물리 콜라이더도 같은 위치로 이동한다.
- 좌우 문설주, 상부 레일, 반투명 유리, 매립 손잡이와 방 이름 상호작용 안내를 제공한다.
- 교실과 특별실 중심에 천장 조명을 추가한다. PointLight는 실제 어두운 주요 방만 켜고 나머지는 발광 등기구로 유지해 비용을 제한한다.

### 남은 구조적 한계

- 현재 가구는 실측 비율이지만 박스 실루엣 중심이라 근거리 재질 정보가 부족하다.
- 복도 벽과 방별 바닥 재질이 충분히 구분되지 않는다.
- 과학실·시청각실 같은 특별실 일부가 일반 교실 가구를 재사용한다.
- 다음 환경 패스에서는 방별 바닥, 벽 하부 몰딩, 게시물, 커튼과 특별실 전용 대형 실루엣을 인스턴싱으로 추가해야 한다.
