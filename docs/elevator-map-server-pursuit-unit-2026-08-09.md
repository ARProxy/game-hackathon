# 엘리베이터 맵·서버·추격 통합 단위

> 작업일: 2026-08-09  
> 기준: `game-design-v4.md` 7장 및 엘리베이터 인수 조건  
> 범위: 실제 승강로, 승객·화물 운행 범위, 서버 운행 승인, 빈 카 유인, AI·술래 이용, 소리 체감

## 기존 불일치

- 상세 엘리베이터 리그는 예전 대형 맵 좌표에 남아 있었고 현재 compact 학교 장면에는 마운트되지 않았다.
- 서버도 예전 좌표를 검사해 현재 맵에서는 정상 탑승이 불가능했다.
- 승객용 계약은 옥상을 포함했지만 서버는 옥상 목적지를 거부했다.
- 클라이언트마다 카 상태가 독립적이어서 멀티 화면의 호출·운행 위치가 달라질 수 있었다.
- 술래와 AI 동료는 엘리베이터를 실제 동선으로 선택하지 않았다.

## 맵 구조

- 북측 순환 복도에 승객용 `evp`, 화물용 `evc` 실제 승강로를 배치했다.
- 각 층 슬래브에서 승강로 보이드를 빼고 배면·양 측 내화벽과 서버 충돌을 일치시켰다.
- 기존 일반 문과 겹치던 지점을 승강장 전용 개구부로 교체했다.
- 지하에는 카에서 안전하게 내릴 수 있는 별도 승강기 로비, 바닥, 외벽, 내부 연결문을 추가했다.
- 지하 내비게이션은 승강로를 관통하지 않고 로비 연결문과 설비실 문을 통과한다.
- 승강로 주변 가구를 제거해 카와 책상·사물함이 겹치지 않게 했다.

## 운행 계약

- 승객용: `B1, F1, F2, F3, ROOF`
- 화물용: `B1, F1, F2, F3`
- 호출, 탑승 위치, 운행 층은 `verticalMapContract.json`의 동일 좌표와 목록을 서버가 읽는다.
- 카 내부 층 선택은 `request_elevator_trip` 서버 승인 뒤에만 모든 클라이언트에서 시작된다.
- 도착 후 실제 actor 층 변경은 승인된 1회 운행 기록과 카 내부 위치가 모두 맞을 때만 허용된다.
- 호출·도착 이벤트를 전 클라이언트에 방송해 멀티 화면의 카 위치를 동기화한다.
- 닫힌 층과 해당 승강기가 서지 않는 층은 서버가 거부한다.

## 전략과 AI

- 빈 카 호출은 승강장 버튼 근처에서 서버에 등록한 뒤 한 번만 도착 핑을 발생시킬 수 있다.
- 빈 카 도착 핑은 실제 도착 층에서 발생하고 술래가 그 층 신호를 추적한다.
- 술래는 계단과 엘리베이터의 접근 거리·이동 시간을 비교해 가까운 실제 경로를 고른다.
- 엘리베이터 이동 중 술래의 이동·포획 권위를 계약 시간 동안 잠근다.
- AI 동료는 인간의 엘리베이터 층 변경을 받고 같은 승강로 입구로 이동한 뒤 동일한 수직 이동을 표현한다.
- 두 AI와 두 술래는 카 내부에서 서로 겹치지 않도록 별도 가로 오프셋을 사용한다.

## 플레이 체감

- 상세 승강장 문, 카, 물리 바닥·측벽·후면, 층 표시와 조작 안내를 현재 학교 장면에 연결했다.
- `0/1/2/3/R` 층 선택 안내를 실제 운행 범위에 맞췄다.
- 모터 기동음과 도착 벨·문 소리를 공용 오디오 엔진에 추가했다.
- 실제 브라우저에서 타이틀→솔로→캐릭터 선택→옥상 플레이, 3D/전체 구조 전환을 확인했다.
- 새 엘리베이터가 활성화된 상태에서 브라우저 콘솔 런타임 오류가 없음을 확인했다.
