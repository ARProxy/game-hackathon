# 기획 1~5 대비 전체 코드 일치도 감사

> 감사일: 2026-08-09  
> 범위: 타이틀부터 결과까지의 실제 솔로 런타임, 서버 권위, AI 동료, 술래, 수직 맵, 층별 미션, 금기어, 멀티플레이 기반  
> 정본: `game-design.md` → `game-design-v2.md` → `game-design-v3.md` → `game-design-v4.md` → `game-design-v5.md`, 그리고 `design-thinking-journey.md`  
> 판정 원칙: 최신 문서가 명시적으로 바꾼 부분만 이전 기획을 대체하며, 코드가 존재하는지보다 실제 한 판에서 그 재미가 작동하는지를 우선한다.

## 결론

현재 구현의 기획 일치도는 **약 67%**로 판정한다.

- 코드·서버 계약 구현도: 약 **78%**
- 플레이어가 실제로 체감하는 기획 구현도: 약 **56%**
- 종합 판정: 약 **67%**

서버 권위, 충돌 계약, 동적 금기어 세대 관리, 서로 다른 층별 미션, 능동 술래, AI 구조와 이동 같은 기반은 상당히 구현되어 있다. 그러나 게임의 정체성을 결정하는 몇 가지 계약이 실제 런타임에서 빠지거나 우회되어 있다. 특히 옥상 이후 계단 이동, 술래의 층간 추격, AI 금기어 비밀 유지, AI의 자유로운 협동 판단, 추론형 최종 주문은 “완료”로 볼 수 없다.

자동 테스트가 통과한다는 사실과 기획대로 재미가 완성됐다는 판정은 분리해야 한다. 현재 테스트는 구현된 계약의 회귀를 잘 막지만, 빠져 있는 게임 경험까지 증명하지는 않는다.

## 항목별 대조

### 1. 시작 흐름

**일치**

- 타이틀, 모드 선택, 솔로 캐릭터 선택, 설정, 나가기 화면이 있다.
- 기획 5에 맞게 사전 질문과 금기어 공개 없이 바로 옥상 게임을 시작한다.

**부분 또는 불일치**

- 멀티 화면은 있지만 방 만들기와 참가 버튼이 비활성이다. 서버에는 방 생성·참가 계약이 있으나 플레이어가 실제로 사용할 수 없다.
- 설정은 전체 음량, 마우스 감도, 자막만 제공한다. 마이크 선택·테스트, STT 언어, 음성 채널, 그래픽, 접근성 설정은 없다.
- 타이틀 클릭 테스트 바로 시작 안내가 일반 시작 화면에 노출된다.
- `Onboarding.tsx`, `ForbiddenReveal.tsx`와 관련 스토어 상태가 죽은 코드로 남아 있어 기획 5를 다시 훼손할 회귀 위험이 있다.

근거: `client/src/components/StartFlow.tsx`, `client/src/App.tsx`, `client/src/components/Onboarding.tsx`, `client/src/components/ForbiddenReveal.tsx`

### 2. 비공개 동적 금기어

**일치**

- 첫 유효 인간 발화 3회를 관찰한 뒤 최초 프로필을 만든다.
- 이후 유효 발화 5회와 45초를 모두 만족해야 교체한다.
- 한 번에 최대 2개만 바꾸고 이전 단어를 최소 1개 유지한다.
- 현재 발화를 기존 세트로 먼저 판정한 뒤 다음 세대를 계산하므로 소급 적용하지 않는다.
- 게임 중 현재 단어, 개수, 교체 시간과 적중 단어를 인간 클라이언트에 보내지 않는다.
- 파이널 진입 시 프로필을 잠그고 결과에서만 이력을 공개한다.
- Ollama가 실패해도 관찰된 실제 명사 후보만 사용하는 로컬 폴백이 있다.

**치명적 불일치**

- AI 회피 문장은 금기어의 첫 글자를 남긴다. 예를 들어 `열쇠`를 `열... 아, 그거 있잖아`로 바꾸는데, 기획 5는 첫 글자·개수·유의어를 포함한 누설을 금지한다.
- 고정 미션 필수어 보호 목록에 1층 방향어와 지하 장치명이 빠져 있다. 반복 대화에 따라 `직진`, `배전반`, `밸브`, `발전기` 같은 필수 발화가 금기어 후보가 될 수 있다.
- 음운 유사도 판정도 즉시 빙결로 이어진다. 낮은 확신에서는 경고나 재확인이 필요하다는 공정성 원칙이 런타임 정책으로 분리되어 있지 않다.
- 결과 화면은 단어 목록만 보여 주며, 각 세대의 활성·종료 시각, 선택 이유, 말버릇 요약, 가장 오래 유지된 단어, 술래 강화 영향을 설명하지 않는다.

근거: `server/app/ai/dynamic_forbidden.py`, `server/app/ai/speech.py`, `server/app/ws/manager.py`, `client/src/components/ResultScreen.tsx`

### 3. AI 동료와 핵심 언어 협동

**일치**

- 두 AI는 별도 기억, 현재 목표, 구조 요청, 술래 기억, 발화 기록을 가진다.
- 술래 회피, 얼어 있는 팀원 구조, 층 이동, 미션 장치 이동, 안전 재배치가 서버 권위로 동작한다.
- AI의 발화도 소리 핑으로 술래에게 전달된다.
- 2층 재확인, 1층 방향 재요청, 3층 누락 의미 피드백은 실패를 즉시 정답 처리하지 않고 재시도를 만든다.

**핵심 불일치**

- 현재 수직 본편은 `round_data = None`으로 시작한다. 따라서 기획 1·2의 핵심이던 “플레이어가 이름 없이 물건을 설명 → AI가 모든 후보를 비교 → 오해·확인 질문·교정 → 물리 탐색” 루프는 레거시 코드에만 있고 실제 메인 플레이에는 연결되지 않는다.
- 현재 AI 판단은 대부분 규칙 기반 상태 머신이다. Ollama/LLM은 동적 금기어 후보 추천에는 사용되지만, 본편 동료의 상황 이해와 후보 추론에는 쓰이지 않는다.
- 옥상, 2층, 1층, 운동장, 지하에서 담당 동료 ID가 미리 고정된다. 두 AI가 같은 정보를 보고 각자 목표를 판단한다는 기획보다 연출된 역할 배분에 가깝다.
- AI 음성은 실제 TTS가 아니라 자막과 짧은 합성 신호음이다. 기획 4의 발화 모드와 세계 안의 목소리 위험이 청각적으로 충분히 체감되지 않는다.

근거: `server/app/game/session.py`, `server/app/ai/companion.py`, `server/app/ai/partner.py`, `server/app/ws/manager.py`, `client/src/components/SoundController.tsx`

### 4. 수직 맵과 층간 이동

**일치**

- 진행은 옥상 → 3층 → 2층 → 1층 → 운동장/지하 순서다.
- 옥상은 안전 구간이고, 현재 층과 바로 이전 층만 접근 가능하며 남은 팀원을 확인한 뒤 이전 층을 닫는다.
- 옥상과 3층 사이에는 실제 U자 계단 경계 이동이 구현되어 있다.
- 맵 렌더, Rapier 충돌, 서버 벽, AI 내비게이션이 같은 학교 구조 데이터에서 파생된다.

**치명적 불일치**

- 3층↔2층, 2층↔1층, 1층↔파이널은 계단 문 앞에서 E를 누르면 목적 좌표로 즉시 바뀐다. 화면에 계단 구조물이 있어도 게임 규칙상 실제로 내려가는 것이 아니다.
- AI 동료도 옥상 계단 외의 층 이동에서는 목적지 좌표로 즉시 바뀐다.
- 술래는 단계 전환 때 `_move_actor_to_slot`으로 다음 층에 재배치된다. 플레이어 소리를 따라 계단이나 엘리베이터로 층을 바꾸는 추격은 없다.
- 엘리베이터 함수는 술래 역할을 허용하지만, 술래 의사결정이 엘리베이터를 선택하고 탑승하는 경로는 없다. 또한 승객 엘리베이터 맵 계약에는 옥상이 있으나 서버 사용 함수는 옥상 목적지를 거부한다.

근거: `server/app/game/vertical_flow.py`, `server/app/ws/manager.py`, `server/app/ai/companion.py`, `server/app/ai/hunter.py`, `client/src/game/VerticalObjectives.tsx`

### 5. 층별 미션과 파이널

**일치**

- 옥상은 순서 기억과 이동, 3층은 의미 우회 방송, 2층은 AI 기호 전달, 1층은 CCTV 음성 관제와 동시 조작이다.
- 운동장과 지하는 서로 다른 협동 구조를 사용하며 최종 경로는 매 판 무작위로 선택된다.
- 실패한 주문은 큰 소리 핑을 만들어 술래 압박을 높인다.
- 필수 미션 실패 횟수 때문에 영구 교착되지 않도록 재시도를 허용한다.

**부분 또는 불일치**

- 각 층에는 사실상 하나의 고정 미션만 있다. 기획의 템플릿 풀, 활성 미션실 무작위 선택, 배치 시드 기반 재플레이 변화는 없다.
- 옥상 역할은 인간=중앙, 동료1=동쪽, 동료2=서쪽으로 HUD에 직접 고정되어 있다.
- 최종 주문 조각 `달빛 · 교정 · 탈출`은 획득 즉시 HUD와 자막에 정확한 단어와 순서로 표시된다. 이는 단서를 조합해 추론하는 주문이 아니라 화면의 정답을 읽는 단계다.
- 운동장과 지하의 역할도 actor ID별로 고정되어 있어 동료 상태에 따른 유연한 역할 교체가 약하다.
- 목표 플레이 시간 10~15분은 실측 자료가 없고, 자동 플레이 테스트는 시간·긴장·재미를 검증하지 않는다.

근거: `server/app/ai/vertical_missions.py`, `server/app/game/vertical_flow.py`, `client/src/components/HUD.tsx`

### 6. 술래와 위협 곡선

**일치**

- 옥상 비활성, 3층 암시 후 제한 추격, 2층 완전 추격, 1층 두 술래 협공, 파이널 광분 단계가 서버 정책으로 존재한다.
- 주 술래는 시야, 청각, 마지막 목격, 신호 조사, 탐색, 게이트 돌진을 사용한다.
- 1층부터 추격자와 차단자의 역할이 분리되고, 차단자는 넓은 시야와 퇴로 차단을 사용한다.
- 시간 경과와 금기어 위반 횟수가 속도·청각·시야 강화에 반영된다.
- 포획은 서버가 같은 층, 거리, 시야선, 현재 위협 단계를 검증한다.

**부분 또는 불일치**

- 층간 추격이 없어서 플레이어가 계단 전환을 통과하면 술래가 실제로 뒤따르는 공포가 끊긴다.
- 3층 암시·제한 순찰 초점에 맵 슬롯이 아닌 절대 좌표가 남아 있다.
- 차단자는 별도 역할이 있지만, 협공이 실제 계단·방화문 선점 확률과 이동으로 이어지기보다 같은 층 내 경로점 선택에 머문다.

근거: `server/app/ai/hunter.py`, `server/app/game/progression.py`, `server/app/ws/manager.py`, `client/src/game/Seeker.tsx`

### 7. 맵, 충돌, 미니맵, 사운드

**일치**

- ㅁ자 학교, 24개 의미 공간, 문·계단·엘리베이터·옥상 구조물이 데이터 계약으로 정의되어 있다.
- 구조 검증은 바닥, 순찰 노드, 계단 보이드, 충돌 여유, 서버 벽 동기화를 검사한다.
- 플레이어, AI, 술래의 이동과 포획에 서버 벽 권위가 있다.
- 미니맵은 같은 월드 슬롯과 현재 층 정보를 사용한다.
- 빙결, 구조, 문 개방, 미션 진행, 발걸음, 술래 근접, 사이렌, 환경 펄스 효과음이 있다.

**제한**

- 본 감사는 코드·자동 계약 감사다. 벽 겹침, Z-fighting, 문 간격, 계단 폭, 카메라 떨림, 미니맵 화면 침범 같은 시각·조작 체감은 실제 화면 검증 없이는 완료 판정할 수 없다.
- 사운드는 Web Audio 오실레이터 중심이고 AI 대사는 음성으로 재생되지 않는다.
- production 번들의 Rapier 엔진 청크가 2MB를 넘으며 코드 분할 경고가 있다. 즉시 오류는 아니지만 로딩과 제출 환경 리스크다.

근거: `client/src/game/compactSchoolData.js`, `client/src/game/verticalMapContract.json`, `client/src/components/MiniMap.tsx`, `client/src/hooks/useSound.ts`

## 우선순위

### P0 — 기획 정체성 또는 진행 체험을 직접 훼손

1. 3층 아래 모든 층간 이동을 실제 계단/경계 이동으로 바꾸고 인간·AI·술래가 같은 이동 규칙을 쓰게 한다.
2. AI 금기어 회피에서 첫 글자 누설을 제거하고, 모든 필수 미션 발화 어휘를 후보에서 영구 제외한다.
3. 현재 수직 본편에 “설명 → 전체 후보 비교 → 오해/확인 → AI 물리 행동” 핵심 루프를 최소 한 층 이상 다시 연결한다.
